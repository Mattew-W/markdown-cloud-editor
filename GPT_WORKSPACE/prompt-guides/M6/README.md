# M6：豆包草稿交付后的个人提示词规则

AI来源为原交付说明第12行。参见 [W1逐项清单](W1核对清单.md)、[原版与返工版diff](../evidence/M6-original-vs-fixed.diff)。正式草稿模块位于另一个目录，是工程重写，不能与同范围返工版混算。

## W1 结论与归因

功能9/11完全完成，2项部分完成：已有输入覆盖保护忽略纯空白；格式损坏只处理JSON解析异常，未检查字段类型或日期。原任务明确要求保护输入和处理损坏，但没有给这些边界样例，属于可通过提示词补全的操作定义；不能证明是模型遗忘。

存储不可用与空间不足已有catch和提示，符合“提示、不崩溃”的原最低要求；统一中文错误是升级，不是完全没实现。无export、固定键、没有版本号均符合独立练习范围。

交付5/6完成，说明没有准确界定未完成部分。验证2/7达标：原记录有刷新/清除；缺中文和损坏用例，保存动作记了读取文案，浏览器留下示例。这里有明确要求未落实，也有验证步骤不够具体。旧审计用“未测ES Module”等后续项指责W1的部分不沿用；仅原要求缺记录就足以需要补正。

## 修正版差异及残余问题

|实际变化|归类|结论|
|---|---|---|
|v2新增parseDraft，检查content类型/savedAt有限数|格式损坏边界补全|未来提示词给语法错、字段错、范围错三类样本|
|v2移到存在性检查后confirm；取消时更新提示；不再trim判断|覆盖保护及反馈修正|明确取消后的内容和消息两种断言|
|describeStorageError统一中文|体验/一致性增强|不能倒说原代码无catch|
|导出函数、type=module、按钮type|后续可复用性增强|W1未规定；不作为原分母|
|正式模块增加用户/文档/会话键、版本、适配器、零DOM|新生产范围|无需在W1加一整套正式规范才能合格|

本轮Node vm探针发现：v2仍接受`savedAt:1e100`，会显示Invalid Date。它不是完整浏览器测试，但已确认日期路径问题；原件和修正版都不改动。后续验收不能只问“有没有Number.isFinite”，应测试最终展示/返回值。

## 给生成任务书 AI 的规则

|ID|依据|下一次写法|

|M6-R5|W1独立页正确；正式模块另写|下周改变交付形态时给固定签名和调用例子，清楚说不再写演示HTML|
|M6-R6|修正版也有日期漏检|验收检查行为，不以“用了某API”当通过；不把优化代码当无条件标准答案|
|M6-R7|用户反馈豆包上下文差|每段重复本阶段必要签名/错误体/输入，不要求记住旧聊天；阶段记录落文件，按文件继续|

## W2 应用

网络客户端目标不变，拆成四段：成功请求；业务/协议错误；超时/网络故障；回归和交付。错误表紧靠该段，204和超时分别给可操作mock。每段列本地输入文件和验收，不再一次贴长稿期待自动记住所有红线。效果待W2收件复盘。

### 新增规则

| ID | 依据 | 下一次写法 |
|---|---|---|
| **M6-R8** | U+2011 污染（提示词唯一真缺口） | **协议字面量必须逐字节 ASCII**：HTTP 头名、Content-Type 匹配串、错误码枚举等按精确字符串匹配的标识符必须是 ASCII。写完扫描非 ASCII 字符，确认只在注释与文案里。`grep -nP '[^\x00-\x7F]' js/*.js`。中文错误文案不在此限（规范要求中文） |
| **M6-R9** | URL 构造用假 base | **禁止 `new URL(path, 'http://dummy-base')`**。传给 fetch 的必须是相对路径，由浏览器按页面 origin 解析。**mock 验的是拼接，不是最终目的地**——断言 `input.pathname` 会掩盖「请求发往错误外域」。断言传入值本身是字符串 |
| **M6-R10** | 记录与交付物不对应（W1/W2 两次同构） | **「未执行项：无」「pass 0 / fail 0」一律不接受**。检查记录必须能由 M1 复跑复现。若 AI 无终端权限，**由本人执行并回贴输出**，不让 AI 代写输出 |

### 给 M1 的机制建议（优先级高于继续加提示词条款）

1. 收件前跑真实 runner，抽取计数与检查记录数字机器比对，不一致直接拒收
2. 交付原始日志文件 + sha256，交接时校验（粘贴片段可编，原始日志难编）
3. 阶段记录加必填「实际执行环境：有终端已自执行 / 无终端已给步骤等用户执行」

**结论：提示词方法论无问题，W2 失败在执行与证据链。规则没有强制力是根因。**
