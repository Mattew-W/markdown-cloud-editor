### 🟠 高-1：冲突回调断言无鉴别力

**问题**
v1 的 `conflict.w5.test.js` 用**源码字符串匹配**做断言：

```js
assert.ok(source.includes('resolveReload('), '...');
assert.ok(source.includes('resolveOverwrite('), '...');
```

**实测（4 个定向变异，v1 全部漏检）**

| 变异 | v1 结果 |
| --- | --- |
| `resolveReload(doc)` → `resolveReload()`（参数传错） | ❌ 未检出 |
| `el.statusText.textContent = '已采用云端版本'` → `'WRONG'`（后续 UI 文案错） | ❌ 未检出 |
| 删除 `editor.setValues({...})`（编辑区不更新） | ❌ 未检出 |
| `resolveOverwrite(state.pendingConflict.serverVersion)` → `resolveOverwrite(999)` | ❌ 未检出 |

**根因**
源码字符串匹配只能检出「整行删除」，检不出「参数错 / 后续 UI 错 / 编辑区不更新」。
而任务书 M5-W5-03 要求的是「每个冲突选择的**点击、回调和后续 UI**」——
v1 的断言对这三点都没有实质覆盖。

**处置（v2 已做）**
重写为**真实本地 HTTP 服务**（`node:http`）驱动全链路：

```
登录 → loadDocumentList → openDocument → 输入 → 防抖窗口
  → PUT 返回 409 VERSION_CONFLICT → syncEngine.enterConflict
  → onConflict 回调 → state.pendingConflict 就位 → 冲突弹窗弹出
  → 点击按钮 → 断言 PUT 实际发出、expected_version 取 serverVersion、
               弹窗关闭、后续 UI 文案正确
```

**复验：4/4 变异全部检出**（fail 分别为 2 / 1 / 2 / 1），还原后 4/4 通过。

## 四、一个执行期缺陷（v2 首次运行时暴露，已修）

**现象**：v2 首次运行 `npm test` **进程不退出**（HANG > 45s，PowerShell 报 exit=1 但无输出）。

**定位**：逐文件运行二分 → 只有 `app.state.w5.test.js` 悬挂 → 再按 `--test-name-pattern`
逐用例隔离 → 定位到第一个用例（dirty）。

**根因链**

1. 该用例断言在输入后 30ms 完成，此时 `sync.js` 的**防抖定时器（1.5s）尚未到期**；
2. 测试结束、HTTP server 已关闭，但定时器仍在挂载 → 到点触发 `flushSave`；
3. PUT 打到已关闭的测试服务 → NetworkError → `handleSaveError` → `scheduleRetry`
   指数退避 → **无限重试循环**；
4. Node 事件循环永不空 → `node --test` 永不退出。

**排除过的无效方案**

| 方案 | 结果 |
| --- | --- |
| 服务器加 `Connection: close` | ❌ undici 连接池仍持有 socket |
| 独立 `undici.Agent` + `agent.close()` | ❌ 全局 `fetch` 不走该 Agent |
| `process._getActiveHandles()` 排查 | ❌ 剩余 Socket 是 stdio，非真因 |

**修复**
走 app.js 的**登出分支**（`app.js:496` 的 `syncEngine.destroy()` → `clearTimers()`），
finally 中先触发登出再关 server。这条路径本就是为「退出登录时清掉已排入的防抖定时器」
设计的，走真实公开入口，未改动被测源码。断言本身仍发生在输入后 30ms，**未放宽**。

**为什么 M5 原交付不遇到这个问题**
她的测试不触发真实 PUT，也就没有「PUT 打到已关闭服务」这条路径。
**引入真实驱动的代价是必须自己管理资源生命周期** —— 这是本轮最值得记下的一点。
