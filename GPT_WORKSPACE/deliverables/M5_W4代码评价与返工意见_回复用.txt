【1】安全测试跑的是 npm 包，vendor 构建从未被执行  ← 任务书明文要求

  任务书第 23 行：「**用运行 vendor 真实版本**验证 script/onerror/javascript: 的 DOM 结果」
  第 14 行：「测试依赖、运行 vendor、版本记录一致」

  你 editor.security.w4.test.js 第 11-12 行是：

      import createDOMPurify from "dompurify";   // ← node_modules
      import { marked } from "marked";           // ← node_modules

  而 vendor 那两个文件，你只是 readFileSync 读进来用正则提取版本号做比对
  （第 94-103 行），**从来没有被执行过**。logs/probe-security.mjs 也一样。
  你自己的 版本对照表.md 第 7-8 行也写了"运行时用 vendor 构建，测试用 npm 包"。

  我用 jsdom 真实执行了 vendor 的 UMD 构建复跑你的两条断言：

      vendor DOMPurify.version: 3.3.3（自述）
      单行链接:  a 元素存在=true  href=null  文本="点我"
      连续 HTML block:  a=无  script=无  事件属性=无

  **结论没变，你的安全断言本身完全正确**，vendor 和 npm 包结果一致。
  但"测的是运行时真正加载的那份构建"这条验收子句，目前没证据。

  改法（补证据，不改结论）：在 editor.security.w4.test.js 加一个用例——

      const dom = new JSDOM("<!DOCTYPE html><html><body></body></html>",
                            { runScripts: "dangerously" });
      dom.window.eval(readFileSync(".../vendor/marked/marked.min.js", "utf8"));
      dom.window.eval(readFileSync(".../vendor/dompurify/purify.min.js", "utf8"));
      // 断言 dom.window.DOMPurify.version === "3.3.3"
      // 再用这份 vendor 实例重复断言：单行链接 a 元素存在 + href === null + 文本保留
      //                              连续 HTML block 无 script / 无事件属性

  探针脚本 logs/probe-security.mjs 同步改成加载 vendor。

  这个做法我 W3 给你做 v2 时就用过（见 reference/M5代修说明.md 第 76-78 行），
  直接抄就行。

【2】「不改变选区」的断言没有鉴别力  ← 任务书明文要求

  任务书第 22 行：「**保存状态变化不重建 textarea、不改变选区**」

  editor.dom.test.js 第 70-84 行这条：

      contentInput.selectionStart = 2;
      contentInput.selectionEnd = 4;
      editor.setValue({ title: "t", content: "abcdef" });   // ← 前后内容相同
      assert.equal(typeof contentInput.selectionStart, "number");   // ← 只断言"是数字"

  两个问题：

  ① `typeof xxx === "number"` 对任何取值都成立，**检不出选区被重置**。
     我构造了一个"坏实现"验证过：让 setValue 把选区推到末尾，选区从 2-4 变成 6-6，
     你这条断言**仍然通过**。

  ② 你让 setValue 前后内容都是 "abcdef"，绕开了重置分支。我实测 jsdom 的行为是
     **赋同值选区不变、赋异值选区会被推到末尾**。你第 81 行注释写的
     "jsdom 中对 value 赋值不主动重置选区"——这句和 jsdom 实现不符。

  另外还有一个**对象错位**：M5-03 要的是"**保存状态变化**"时不重建 textarea，
  但你现有三个 DOM 用例测的都是 setValue（文档加载路径）。而"状态变化"恰恰是
  你本周新增的 renderSyncState（ui-feedback.js 第 229-238 行）的职责——
  它写 #syncBadge / #statusText，结构上不碰 textarea，但**没有断言证明这一点**。

  改法：

  a) 选区断言改成具体数值：记录 setValue 前后的 selectionStart/selectionEnd，
     断言不变。⚠ 这里要先想清楚语义：**加载路径**（setValue 换文档）允许重置，
     **保存路径**（状态变化）禁止重置。如果你打算用"内容不同"的场景，
     要在用例注释里把这个区分写明。

  b) 新增一例：建一个含 <textarea> 的 DOM，调 renderSyncState（dirty/saving/synced
     和 storage failure 各一次），断言 textarea **节点身份不变**（strictEqual）、
     selectionStart/selectionEnd 不变、previewElement 不被重建。
