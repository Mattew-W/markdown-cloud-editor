# 给 M1 的同步交接表（M6 · W5-04）

本表是 M6 交给 M1（sync/app 与总集成）的交接面说明，含 API 响应/错误映射、草稿接口、触发条件、交接用例、与 M5 的事件核对清单，以及断网/恢复的完成层次。全部结论来自本轮实测，日志见 `logs/`。

## 1 API 客户端契约（`frontend/js/api.js`）

### 1.1 响应阶段与超时

| 阶段 | 可观察事实 | 证据 |
|---|---|---|
| 请求发出 | `fetch` 被调用，路径为 `/api/v1…` 相对路径，由页面 origin 解析 | `W5-01-g` |
| **收到响应头** | `fetch` promise resolve —— 此时正文尚未读取 | `W5-01-a`（事件序列 `headers` 先于 `body-start`） |
| **正文开始** | 仅 2xx 或声明为 JSON 的错误体才调用 `response.json()` | `W5-01-a/b`（`jsonCalls` 计数） |
| 正文阶段超时 | 10 秒 `AbortController`，计时覆盖 fetch 与正文读取；请求结束在 `finally` 清除定时器 | `W5-01-f2` |
| 断连 | 正文读取阶段连接中断 → `NetworkError`（不是 `ApiError`/`ProtocolError`） | `W5-01-d`（500 响应）、`W5-01-f`（服务关闭） |

上层含义：**不要把“超时”当成“没发出”**。超时与断连都发生在正文阶段，服务端可能已经处理了请求，保存结果属于“结果未知”，要走 `sync.js` 的核对（§6）而不是直接重发。

### 1.2 错误映射（`error.code` → 异常类，保留 status/code/details/requestId）

| HTTP | `error.code` | 异常类 | 上层动作（`sync.js` 现状） |
|---|---|---|---|
| 400 | `BAD_REQUEST` | `InvalidInputError` | `INVALID`，暂停自动重试，等用户修正 |
| 401 | `UNAUTHORIZED` | `AuthError` | `AUTH_REQUIRED`，暂停重试 |
| 404 | `NOT_FOUND` | `NotFoundError` | 云端不可用分支 |
| 409 | `USERNAME_TAKEN` | `ConflictError` | 注册/改名的冲突提示 |
| 409 | `VERSION_CONFLICT` | `VersionConflictError`（带 `serverVersion`） | `CONFLICT`，禁止自动覆盖 |
| 413 | `PAYLOAD_TOO_LARGE` | `TooLargeError` | `INVALID` |
| 429 | `RATE_LIMITED` | `RateLimitedError`（保留 `retryAfter` 原始头） | 遵守 `Retry-After`，不用退避表 |
| 503 | `SERVICE_UNAVAILABLE` | `ServiceUnavailableError` | 退避重试 |
| 500 | `INTERNAL_ERROR` | `ServerError` | 退避重试 |

无标准错误体时的统一规则（**实测**：`W5-01-b/c/c2`）：

| 情形 | 结果 |
|---|---|
| 非 JSON 错误体（`text/html`、`text/plain`、`application/octet-stream`…） | `ApiError` 基类；`status` 保留；`code=null`；**不解析正文**；不把 HTML 整段塞进 `message` |
| 声明 JSON 但解析失败 | `ProtocolError`（`status` 保留） |
| 401 且无标准错误体 | 仍归 `AuthError`（否则上层无法进 `auth_required`） |
| `VERSION_CONFLICT` 缺有效 `server_version` | `ProtocolError`，不编造版本号 |

九类错误码在**同一次真实传输循环**内验证：`W5-01-e`（这会暴露“只测了 8 类”的历史缺口）。

## 2 草稿接口（`frontend/js/drafts.js`）

| 接口 | 语义 | 关键约束 |
|---|---|---|
| `buildDraftKey({userId, docId, sessionId})` | 键 `markdown-editor:draft:<userId>:<docId>:<sessionId>`（各段 `encodeURIComponent`） | 三个字段任一为空 → `TypeError`（**匿名不落盘**，`W5-02-c`） |
| `parseDraftKey(key)` | 反解三段；不合格返回 `null` | 供枚举时判定归属 |
| `saveDraft(draft, storage)` | 写 `snake_case` 记录（`user_id/doc_id/edit_session_id/base_version/title/content/local_revision/recorded_at`） | 存储故障抛 `DraftStorageError(reason=quota/unavailable)` |
| `readDraft(key, storage)` | 读回 camelCase 对象；**损坏/键不符 → 抛 `DraftStorageError(reason='corrupt')`** | 键内三段必须与记录内三段一致，否则视为损坏。**必须 try/catch，不能当 `null` 处理**（契约 `INTERFACES.md` §212 明写抛） |
| `listDrafts({userId, docId?}, storage)` | 按前缀枚举；`recorded_at` 倒序；损坏项带 `corrupt` | 不静默丢弃损坏项（`W5-02-h`） |
| `discardDraft(key, {sessionId, localRevision, content}, storage)` | **三重核对**（会话 → 修订号 → 内容）全等才删 | 任一不等返回 `false`；键不存在返回 `true`（幂等）；**删除时存储故障抛 `DraftStorageError`**（`W5-03-g`） |
| `clearSessionDrafts(parts, {cloud, confirmedKeys, force}, storage)` | 只清理“已被云端覆盖”的历史草稿 | `cloud` 必须**完整**（`version` + `title` + `content`）；`base_version > cloud.version` 不删；内容（含标题）不同不删；`force` **上层禁用** |
| `classifyRestore(draft, cloud)` | **`'adopt_cloud'` / `'confirm'` / `'conflict'` 三分支**（契约 `INTERFACES.md` §248/§552 冻结） | 不得恒走某一分支（既有用例断言）。**注意：没有 `keep_local`、没有 `hidden`**——这四个词是本表初版的笔误，M1 审核已更正 |

| `createDraftWriter({storage, delay, clearDelay})` | 250ms 合并窗口写入器：`schedule/flush/flushAll/cancel/pending` | `cancel` 必须真正清掉定时器（`W5-02-g`）；`flushAll` 必须先写后清 |

## 3 触发条件（什么时候该调哪个）

| 场景 | 必须做的事 | 依据 |
|---|---|---|
| 用户键入 | `onInput` → `writeDraft()`（250ms 合并）→ 调度保存 | SYNC §9.4 |
| **切换文档 / 退出登录前** | **先 `flushDraft()` 再切**，否则窗口内编辑可能丢 | SYNC §8.1（M1 待修，见 §6 F-03） |
| 保存成功 | 仅当 `(sessionId, savingRevision, content)` 与发送快照全等时 `discardDraft` | INTERFACES §C9 |
| 保存成功但期间又有新修订 | **不清**；保持 `DIRTY` 并继续保存 | `W5-INT-b` |
| 保存失败（网络/超时/5xx） | **不清**；`RETRY_WAIT` + 退避 | `W5-INT-c` |
| 409 冲突 | **不清**；`CONFLICT`，等用户选；阻塞期不写服务器 | `W5-INT-d` |
| 用户确认“采用云端” | `flushDraft()` → 三重核对删除 → `initSession` | `W5-INT-f`（草稿层） |
| 删除文档 / 批量清理 | 只能用 `confirmedKeys` 或完整 `cloud`；**禁止 `force:true`** | 既有用例 + `W5-03-f` |

## 4 与 M5 的“事件—可见状态”核对清单（**未实机核对，待 M5 与 M1 执行**）

静态对照（`frontend/js/app.js:154-194`，本轮只读源码，没有点按）：

| 引擎状态 | 徽章文案 | 状态行文案 | 触发条件（引擎侧可复现入口） | 本轮是否实测 |
|---|---|---|---|---|
| `SYNCED` | `✓ 已同步` | 所有更改已同步至云端 | `W5-INT-a` 末尾 | 仅引擎侧 |
| `DIRTY` | `• 本地已备份` | `payload.message`，缺省“已在本地备份” | `W5-INT-b` 末尾 | 仅引擎侧 |
| `SAVING` | `⏳ 保存中…` | 正在与云端同步… | 任意一次 `flushSave` 起始 | 仅引擎侧 |
| `RETRY_WAIT` | `⚠️ 等待重试` | 缺省“网络中断，已在本地备份，稍后重试” | `W5-INT-c` | 仅引擎侧 |
| `AUTH_REQUIRED` | `🔒 需要登录` | 登录已失效，草稿已在本地备份，请重新登录 | 401 | 仅引擎侧 |
| `CONFLICT` | `✕ 版本冲突` | 检测到并发编辑冲突 | `W5-INT-d` | 仅引擎侧 |
| `INVALID` | `✕ 校验错误` | `payload.error`，缺省“文档内容不合规” | 400/413 | 仅引擎侧 |

待 M5 点按核对的点（有浏览器与后端的环境执行）：

1. `DIRTY` 且 `storageOk=false` 时，状态行**不得**显示“已在本地备份”（应显示“本地备份失败”，`sync.js` 已透传 `message`）。
2. 七个状态徽章的 class 与文案是否与上表逐个一致；切换状态时是否残留上一个状态的 class。
3. 冲突弹窗两个按钮（用云端 / 用本地）各自之后的徽章走向；选“用云端”后是否回到 `SYNCED` 且草稿被清理（依赖 §6 F-01 修好）。
4. 删除文档前是否给出“未同步内容”提示与下载入口。
5. 刷新页面后恢复横幅三分支（采用本地 / 采用云端 / 未同步）是否与 `classifyRestore` 的返回值对应。

| 场景 | 本轮做到哪一层 | 证据 |
|---|---|---|
| HTTP 断连、正文中途断开、服务端关闭 | **真实链路**（本机 127.0.0.1 真实 TCP + 真实 `fetch`/`AbortController`） | `logs/w5_01_http.log`（`W5-01-d/f/f2`） |

## 6 待 M1 处理（含本轮发现的源码缺口）

### F-01 `resolveReload()` 未把注入存储传给 `discardDraft`（**必修**）

- 位置：`frontend/js/sync.js:921`；对照 `sync.js:581-589`（`discardOwnDraft` 有传 `this.storage`）。
- 证据：`logs/probe_resolve_reload.log` —— 恢复后草稿仍 1 条，并打印 `丢弃本地草稿失败：浏览器禁止本地存储`（`drafts.js:437 ← sync.js:921`）。
- 修法：`drafts.discardDraft(draftKey, {...}, this.storage)`。
- 修完后复跑入口：`node --test js/tests/drafts.w5.integration.test.js` 应仍全绿；再把 `W5-INT-f` 的草稿层结论升级为端到端结论（补一条走 `engine.resolveReload()` 的用例）。

### F-03 `initSession()` 切换文档前不 flush 待写草稿（**建议必修**，SYNC §8.1）

- 位置：`frontend/js/sync.js:243-266`（只 `clearTimers()`，未 `flushDraft()`/`draftWriter.cancel()`）。
- 证据：`logs/probe_switch_doc.log` —— 切换前 docA 草稿 0 条，切到 docB 再输入并过 250ms 后，**docA 仍 0 条、docB 1 条**：docA 窗口内的最后一批编辑从未落盘（`schedule()` 直接覆盖了 `pendingDraft`）。
- 影响：用户在 A 文档打完最后一句立刻切文档，A 的这段编辑既没进草稿也没进云端；刷新后按草稿恢复时会少一段。
- 建议：`initSession` 或 `app.openDocument` 在切换前调用 `flushDraft()`（失败则提示并中止切换），或以“先 flush 再说”的顺序调用。

### F-02 材料文档的清单自指纹不一致（**由发题方/M1 确认**）

`基线说明.md` 写 `daa66299…`，包内 `SHA256清单.txt` 实际为 `eefc7aef…`（原始与 LF 归一一致）。条目核对 109/109 通过，不影响基线可用性，但基线身份应由 M1 以清单为准确认。

### 其它建议（不阻塞）

- `clearSessionDrafts` 的 `force` 分支建议在函数内加“调用方白名单/`confirmedKeys` 必填”的守卫，避免上层再次误用 `force:true`（既有测试只是断言“目前没用”）。
- `discardDraft` 的“键不存在返回 true”对调用方是幂等友好，但会掩盖“键拼错”的问题；建议调试模式下打印一次键。
