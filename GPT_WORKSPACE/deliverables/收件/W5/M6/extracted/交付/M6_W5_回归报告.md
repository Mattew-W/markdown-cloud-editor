## 3 结论

- W5-01：真实 HTTP 阶段四个判定（响应头/正文开始、断连、正文超时、非 JSON 错误体统一映射）**全部可观察取证**，并且测试服务与挂起请求都被显式关闭（关闭耗时 < 3s，超时定时器在 `finally` 清除）。
- W5-02：草稿隔离按**实际键字符串、raw 记录、读回值**三者断言；匿名不留痕；迟到回调只落旧身份键；`cancel` 是“真的取消”（到点后存储写入 0），不是统计调用。
- W5-03：条件删除的四种保存结果（成功且匹配 / 成功但快照不匹配 / 失败 / 409）与“较新草稿”分支均有断言，且都有正对照，避免“恒不删”式的伪绿。
- 全量回归：236/236 通过，无 cancelled/skipped/todo。

## 5 发现与契约冲突

### F-01（源码缺口，责任方 M1）`resolveReload()` 的草稿清理没有作用在注入存储上

- 相关路径：`frontend/js/sync.js:921`（`resolveReload` 内 `drafts.discardDraft(draftKey, {...})`，只传两个实参）；对照 `frontend/js/sync.js:581-589`（`discardOwnDraft` 显式传 `this.storage`）。
- 观测：`logs/probe_resolve_reload.log`
  `resolveReload 前草稿条数 = 1` → `resolveReload 后草稿条数 = 1`，并打印
  `丢弃本地草稿失败: DraftStorageError: 本地备份失败：浏览器禁止本地存储`，调用栈指向 `drafts.js:437 ← sync.js:921`。
- 影响：`drafts.js:437` 走 `defaultStorage()`。生产页面里默认存储与引擎用的是同一个 `localStorage`，因此**看不出来**；但一旦存储被注入或封装（测试、离线封装、隐私模式降级、配额受限替换实现），“采用云端版本”这一步的草稿清理会落到另一个存储，草稿留在原地，下次打开文档会再弹恢复提示（内容已与云端相同，属误报）。
- 建议改法（一行）：`drafts.discardDraft(draftKey, {sessionId, localRevision, content}, this.storage)`。
- 本轮处理：M6 不改 `sync.js`（按提示词由 M1 负责 sync/app），因此在草稿层用 `W5-INT-f` 覆盖“flush → 三重核对 → 删除”的序列与负对照，并把此项列为交接事项；`W5-04` 的“恢复后无残留”**只算草稿层通过，不算端到端通过**。

### F-02（材料文档不一致，责任方 M1/发题方）

见 §1.3：`基线说明.md` 记录的清单自指纹与包内 `SHA256清单.txt` 实际指纹不同。条目核对不受影响，仅提示基线身份确认以清单为准。

### F-03（源码缺口，责任方 M1）`initSession()` 切文档前不刷新待写草稿

- 相关路径：`frontend/js/sync.js:243-266`（`initSession` 只 `clearTimers()`，既未 `flushDraft()` 也未 `draftWriter.cancel()`）；契约依据 `docs/SYNC.md §8.1`（切换文档前先保存本地草稿）。
- 观测（`logs/probe_switch_doc.log`）：
  `切换前 docA 草稿条数 = 0` → 切到 docB、输入并过 250ms 后
  `docA 草稿条数 = 0`、`docB 草稿条数 = 1`。
- 机制：`createDraftWriter.schedule()` 在已有定时器时只替换 `pendingDraft`，于是新文档的输入直接覆盖了旧文档窗口内的快照，旧文档这批编辑**从未落盘**。
- 影响：用户在 A 文档写完最后一句立刻切文档，这段内容既不在草稿也不在云端；刷新后按草稿恢复会少一段（丢稿窗口 = 250ms 合并窗口）。
- 建议改法：`initSession` 入口处先 `flushDraft()`（失败则提示并中止切换）；或在 `app.openDocument` 里“先 flush，再取新文档，再 initSession”。
- 本轮处理：同样交 M1；M6 只测草稿层（`W5-02-e` 证明迟到回调不跨键、`W5-INT-e` 证明两条记录互不覆盖），不声称已覆盖真实切文档路径的完整性。
