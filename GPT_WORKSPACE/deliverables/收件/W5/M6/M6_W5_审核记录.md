## 六、🔴 发现并修复的三处源码缺口（M6 取证，M1 修复）

M6 用**可运行的诊断探针**证明了这三处，不是文字描述。M1 **全部独立复现**后修复。

### F-01 `resolveReload()` 漏传 `storage`（**已修复**）

**位置**：`sync.js:921`；对照 `sync.js:581-589`（`discardOwnDraft` 有传 `this.storage`）。

**M1 独立复现**（探针实跑，输出与她的日志逐字一致）：

```
[probe] resolveReload 前草稿条数 = 1
丢弃本地草稿失败: DraftStorageError: 本地备份失败：浏览器禁止本地存储
    at defaultStorage (drafts.js:100:13)
    at Module.discardDraft (drafts.js:437:29)
    at SyncEngine.resolveReload (sync.js:921:16)   ← 就是这里
[probe] resolveReload 后草稿条数 = 1     ← 草稿没被清掉
```

**铁证**：`sync.js:579-580` 的注释自己写着「**必须传同一个 storage 适配器**——否则注入的存储与实际写入处不是同一个，会去读默认存储」。**第 921 行正好违反了自己代码里的既有约定。**

**影响**：生产页面里两者恰好都是 localStorage，看不出问题；一旦换成注入/封装的存储适配器（测试、离线封装、隐私模式降级），这次清理就落到别处，**草稿留在原地，且只打一条 `console.warn` 静默失败**。

**修复**：`drafts.discardDraft(draftKey, {...}, this.storage)`

**修复后验证**：草稿 1 → **0** 条。

### F-03 `initSession()` 切换文档前不 flush 待写缓冲（**已修复**）

**位置**：`sync.js:243-266`（原只 `clearTimers()`）。

**M1 独立复现**（与她的日志逐字一致）：

```
[probe] 切换前 docA 草稿条数 = 0
[probe] 切换并继续编辑后 docA 草稿条数 = 0    ← 旧文档的编辑从未落盘
[probe] 切换并继续编辑后 docB 草稿条数 = 1
```

**影响**：用户在 A 文档打完最后一句立刻切文档，A 的这段编辑**既没进草稿也没进云端**；刷新后按草稿恢复会少一段。

**修复**：`initSession()` 开头调用 `this.flushDraft()`。

**关键顺序**：`flushDraft()` **必须在改写 `docId`/`editSessionId` 之前**——否则会用新会话的键写旧内容。（`draftWriter.schedule()` 会快照 userId/docId/sessionId，所以 flush 写的是排入时的旧键；但若 flush 抛错，改写之后才处理就来不及了。）

**修复后验证**：docA 草稿 0 → **1** 条。
