二、三项阻断
------------

【阻断-1】T13 缺「保存全过程 + 焦点/选区/光标」

  要求：任务书 M5-W6-01「使用中文输入法录下组合开始、上屏和保存全过程，
        记录焦点、选区、文本与光标」；矩阵 T13「真实中文 IME 录屏，保存时不干扰节点和选区」。
  实际：只有 3 张静态截图（组合态 ×2、上屏态 ×1）。没有组合开始帧、没有保存过程、
        没有 activeElement、没有 selectionStart/End、没有光标位置。
  证据：交付说明.md:59/80、验收表.md:11、回归报告.md:42、截图索引.md:30 均自述「待联调」。
  性质：**W5 被我判「只截了候选框与上屏、没记光标与选区」的阻断点原样重复。**

  处置（v2）：
    · M1 用 Chrome CDP 实测补上 DOM 层读数（evidence/probe_t13_dom_state.json）：
        输入前  activeElement=docContent，选区 8–15
        触发 input（会重写预览 innerHTML）后：焦点不变，选区仍 8–15，sameNode=true
        合成 composition 期间与之后：焦点不变、节点同一、值尾部「中文」正常上屏
        7 种状态轮换期间：sameNode=true 全部成立，选区保持 5–11 不变
    · **但真实 IME 保存全过程仍待本人**。M1 的 composition 事件是 CDP 合成，
      只证明「DOM 层在组合期间不重建节点、不改选区」，不能替代真实输入法录屏。
      这一条在 v2 文档里反复写明，没有拿 M1 的证据去冒充本人完成。


【阻断-2】M5-W6-02 四种可见状态只做了「未同步」一种

  要求：任务书「在实际页面复核未同步、等待重试、冲突以及本地备份失败的提示与操作。
        验证冲突重载和覆盖分别落到预期版本，确认下载文案与实际下载行为」。
  实际：只复核了首屏「未同步」徽标；其余三种与冲突落版本、横幅下载全部写「待联调」。
  证据：验收表.md:12、截图索引.md:35、回归报告.md:57。

  处置（v2）：
    · M1 起同源 mock API 驱动 app.js 真实路径（不是给 DOM 打桩），实测六种状态：
        未登录      未同步 / 系统就绪
        登录后      ✓ 已同步 / 所有更改已同步至云端
        输入后      • 等待本地备份 / 正在准备本地草稿
        PUT 429     ⚠️ 等待重试 / 错误: 请求过于频繁
        PUT 409     ✕ 版本冲突 / 检测到并发编辑冲突，弹窗 v7 / v5
        Quota       (徽标保持原同步态) / 本地备份失败：存储空间不足
      截图 6 张 + 原始读数 evidence/states/。
    · 冲突两按钮落版本（evidence/conflict/）：
        「强制覆盖」→ PUT expected_version=7（取服务端版本，非本地 v5），落 v8
        「重新载入」→ 先 GET 拉云端、UI 切云端正文、落 v9
    · 顺带确认 W5 的冲突 C-1 已闭合：存储失败文案现在是 INTERFACES §2.5 冻结的
      「本地备份失败：存储空间不足」，不再是「本地备份失败（quota）」带英文码。
    · 仍待本人/真实后端：断网恢复与草稿回写、横幅「立即下载 Markdown」的实际下载回读。


【阻断-3】理解题先给 4 条「参考方向」，再给「本人作答」

  要求：任务书「原理解题由本人重新作答」；先读我「本人作答、复跑与签名由本人填写」。

五、一处需 M6/M1 复核的观察（不是 M5 缺陷）
-------------------------------------------

evidence/conflict/conflict.json 记录：点「重新载入」后，GET 云端之后**仍发出一次 PUT**
（expected_version=8，携带本地内容）。

探针的 mock 在 GET 时硬编码返回云端正文、不做服务端侧写入，
因此**无法判定这次 PUT 是否会把本地内容覆盖回云端**。
这属于 sync.js 的时序问题，应由 M6 / M1 在真实后端复核。
本文不据此认定任何一方有缺陷——同样，也不据此认定没有。
