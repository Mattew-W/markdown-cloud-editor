## 3. 失败处置（按现象查表）

| 现象 | 先查 | 处置 |
|---|---|---|
| 注册/登录 500 | 表属主是否 `markdown_editor`；`.env` 的 `DATABASE_URL` 指向的库是否已建表 | 改属主或重跑 `0001_init.sql`；不要用 postgres 建的库直连应用 |
| 401 `UNAUTHORIZED` | token 是否来自本实例（换库/换 `JWT_SECRET` 会全失效）；是否过期（1h） | 重新登录；不要在前端保留旧 token |
| 409 `VERSION_CONFLICT` | 读 `details.server_version`，与本地 `state.currentDoc.version` 比 | 走冲突弹窗：`resolveReload` 采用云端，或强制覆盖；禁止静默重试旧基准 |
| `等待重试` 不自动恢复 | Actix / PostgreSQL 是否都起来了；`/health` 状态 | 先恢复服务再等退避（1s 起）；连续失败会一直保留草稿，不丢内容 |
| 存储失败横条一直显示 | 是否已切换/删除文档（F-04 观察项） | 刷新页面或切换文档可清；不影响云端保存 |
| 429 `RATE_LIMITED` | `Retry-After` 秒数；同源入口是否漏传 `X-Real-IP`（否则所有用户共享一个桶） | 等窗口结束；反代务必保留真实客户端 IP |
| 413 返回 400（F-01） | 请求体是否 > 2 MiB | 前端提前截断/提示；**M1 已修**（`OverflowKnownLength` + `Overflow` 双匹配 → 413） |
| 非法 UUID 返回 404 纯文本（F-02） | 前端是否把非 UUID 拼进 URL | 前端先校验 UUID；**M1 已修**（`PathConfig::error_handler` → 400 JSON） |

## 5. 移交 M1 的 5 条新事项

1. **F-01** JSON 体 > 2 MiB → 400（应 413）：**根因已由 M1 定位并修复**——`src/routes/mod.rs` / `src/routes/auth.rs` 的 `JsonConfig` 错误映射**只匹配了 `JsonPayloadError::Overflow`**（无 `Content-Length` 时触发），而浏览器与常规客户端都带 `Content-Length`，实际命中 **`JsonPayloadError::OverflowKnownLength`**，落到 `other` 分支被映射成 `400 BAD_REQUEST`。**修法是同时匹配两个变体**（已修，实测 413 `PAYLOAD_TOO_LARGE`）。
   > **注意：原建议"把 `JsonPayloadError::Overflow` 映射到 413"不准确**——代码里**已经**映射了 `Overflow`，只照此改会原地打转。
2. **F-02** 非法 UUID → 404 纯文本（应 400 JSON）：**根因已由 M1 定位并修复**——Path 提取器失败走 actix 默认响应。修法是给 documents 路由挂 `PathConfig::error_handler`，统一映射 400 JSON（已修，实测 400 + `application/json`，且「资源不存在」仍由 handler 的 `AppError::NotFound` 返回 404，二者语义分离）。
3. **F-03** 冲突“重新载入云端”后列表版本号未刷新：`app.js` 在 `resolveReload` 成功后调用 `loadDocumentList()` 或就地更新该项。
4. **F-04** 删除文档后存储失败横条未隐藏：`deleteCurrentDocument` / `openDocument` 里重置 `storageBanner`。
5. **F-05** 下载文件名取陈旧标题：`downloadMarkdown` 改用编辑器当前标题（或保存后同步 `state.currentDoc.title`）。

> 以上均只取证、未改代码，符合“固定基线只验收”的要求；是否修改由 M1 决定。
