## 2. M1 需要接线的调用（含真实返回值）

```js
import {
  createEditSessionId, buildDraftKey, saveDraft, readDraft, listDrafts,
  discardDraft, clearSessionDrafts, createDraftWriter, DraftStorageError,
} from './drafts.js';

// 打开文档：userId 必须是**当前登录账号**；sessionId 每次打开/切换文档重新生成
const sessionId = createEditSessionId();

const writer = createDraftWriter({ storage: window.localStorage });
```

| 调用 | 真实返回 / 抛出 | 接线要点 |
|---|---|---|
| `saveDraft(draft[, storage])` | `{ key: 'markdown-editor:draft:<userId>:<docId>:<sessionId>', recordedAt: 'ISO 字符串' }` | 成功**只能**显示“已在本地备份”；**禁止**改 `synced/dirty`（`SYNC.md` §4.4） |
| `readDraft(key[, storage])` | 合法记录（snake_case，8 字段） 或 `null` | `corrupt` 时抛 `DraftStorageError{reason:'corrupt'}`；界面提示“本地备份已损坏，已忽略”，**不得显示 Invalid Date** |
| `listDrafts({userId, docId?}[, storage])` | 记录数组（按 `recorded_at` 降序；损坏项为 `{corrupt:true, key, user_id, doc_id, edit_session_id}`） | 枚举结果**不得自动恢复**（`SYNC.md` §9.5），交用户选择；损坏项按类型提示 |
| `discardDraft(key, {sessionId, localRevision, content}[, storage])` | `true` 已删；`false` 核对未通过；目标不存在 → `true` | `false` 时**必须**保留编辑器内容/状态，提示“草稿已有新修改，暂不能丢弃”；**不得**按成功处理 |
| `clearSessionDrafts({userId, docId, sessionId}, {cloud?, confirmedKeys?, force?}[, storage])` | `{ removed: string[], kept: string[] }` | `cloud` 必须同时给 `version`+`title`+`content`，缺一即不删（保守）；`kept` 一律不得当作已丢弃 |
| `createDraftWriter({storage, delay?, clearDelay?})` | `{ schedule, flush, flushAll, cancel, pending }` | 切换文档前 `flush()`；放弃待写内容用 `cancel()`；`schedule` 不落盘直到 250ms 到点。**⚠ 原表列出的 `now?` 参数无效**——`drafts.js:705` 赋值后全文未使用，注入不生效，M1 接线时不要依赖它（详见下方 §2.1） |
| `DraftStorageError` | `{ name:'DraftStorageError', reason:'quota'|'unavailable'|'corrupt'|'serialize', message:中文, detail:内部 }` | `message` 可直接展示；`detail` **不得**展示给用户 |

### 2.1 `now` 注入参数无效（M1 审核补充，2026-11-11）

本表初版把 `now?: () => string` 列为 `createDraftWriter` 的可注入参数。**M1 审核实测发现该注入无效**：

```
$ grep -n "\bnow\b" frontend/js/drafts.js | grep -v '^\s*[0-9]*:\s*\*'
705:  const now = options.now ?? isoNow;
```

**全文仅此一处**——`now` 赋值后从未被读取。传入自定义 `now` 不会影响 `recorded_at` 的生成。

- **这不是本周引入的缺陷**，是基线遗留（`drafts.js` 该段自 M1 W2 代修起即如此）。
- **M1 接线时不要依赖 `now`**；需要控制时间戳请直接用 `saveDraft` 写入后自行覆盖，或提出修复请求。
- 若要修复，最小改动是把 `writeNow()` 里的 `now()` 真正用上——但这属生产代码变更，需走变更流程，且本周范围不含此项。

完整可运行样例：`证据/call_samples.mjs`，真实输出见 `日志/08-call-samples.log`。

## 3. 必须遵守的顺序约束（本次实测发现）

**切换文档 / 退出账号 / 清理草稿时**：

```
1. writer.flush()        // 有未确认输入：先落盘（SYNC §8.1 第 1 步）
   或 writer.cancel()    // 明确放弃这段待写内容
2. clearSessionDrafts(...)   // 再做清理
```

实测（`证据/probe_buffers.mjs`，输出 `日志/07-probe-buffers.log`）：

| 顺序 | 结果 |
|---|---|
| 直接 `clearSessionDrafts()`（既没有 cancel 也没有 flush） | 清理后 0 条，但待写缓冲到点后**写回旧会话草稿**（复活） |
| 先 `cancel()` 再清理 | 不复活（旧定时器已被取消，`fire` 返回 false） |
| 先 `flush()` 再清理 | 不复活 |

**这不是 `drafts.js` 单方面能修的**：写缓冲器不知道“哪些键刚被清理”。所以本项作为**接线约束**交给 M1；本次已在 `drafts.js` 侧把“取消必须走注入时钟”修好（否则 `cancel()` 对假时钟无效，顺序再对也会复活）。

## 4. 文案禁令（`SYNC.md` §4.4 / `INTERFACES.md` C9）

| 场景 | 允许 | 禁止 |
|---|---|---|
| 草稿写入成功 | “已在本地备份” | “已同步”“保存成功”“已保存”；**不得**因此改 `synced`/`dirty` |
| 草稿写入抛错（quota/unavailable/serialize） | 显示 `DraftStorageError.message` + 保留内存内容 + 提供 Markdown 下载 | 显示“备份成功/已保存”；清空编辑器；把异常吞掉 |
| 删除返回 `false` | “草稿已有新修改，暂不能丢弃” | 清空编辑器；按“已丢弃”处理 |
| 清理返回的 `kept` | 按存在提示 | 当作已丢弃/已清理 |

> **保存抛错被吞掉后显示“备份成功”，是本模块要防的事故里最严重的一类**：用户会以为内容已上云/已落盘而关闭浏览器，实际两份都没有。样例第 6b 组演示了正确行为（抛错保留 pending，恢复后补写）。
