### 4.1 发现并修复的缺陷（真实 HTTP 无关，属可注入依赖的取消语义）

**现象（修复前，先跑新用例得到的红）**：

```
  error: flush 必须取消待触发定时器
  1 !== 0
not ok 22 - M6-04 flush 真正取消注入时钟的旧定时器，旧定时器不得提前写走新草稿
not ok 23 - M6-04 flushAll 落盘且不再触发第二次写入
# tests 25 / # pass 20 / # fail 5
```

（第 5 个失败是我自己用例的缺陷：`classifyRestore` 的入参是**落盘记录**，我最初传了 camelCase `baseVersion`，导致 `base_version` 为 `undefined`。**不是源码缺陷**，已改用 `base_version` 后通过——按 M6-R21 先排除用例自身的时序/取值错误。）

**根因**：`createDraftWriter` 的取消路径写死 `clearTimeout(timer)`。注入可控/假时钟时，句柄不在全局时钟名下，`flush()/flushAll()/cancel()` 取消是空操作 → 旧定时器仍到点触发 → 把**之后新排入**的草稿提前写走（实测：`flush()` 后 `clock.size()` 仍为 1，旧定时器触发后存储里已是新草稿 `B`，而它本应还在 250ms 窗口内）。这与 M6-R19“假时钟必须模拟被模拟对象的完整语义”是同一问题在**实现侧**的对应。

**最小修复**（`frontend/js/drafts.js`，生产代码 +7 行、改 3 行，见 `diff/drafts.js.diff`）：

```js
const clearDelay = options.clearDelay ?? ((handle) => clearTimeout(handle));
// flush / flushAll / cancel 中的 clearTimeout(timer) → clearDelay(timer)
```

- 未改任何冻结签名（`createDraftWriter` 本就不在冻结清单内，`INTERFACES.md` §2.3 只冻结 7 个导出；新增的是**可选**参数）
- 默认值仍是全局 `clearTimeout`，**生产行为零变化**（`api.js` 一字未动）
- 修后：`# tests 25 / # pass 25 / # fail 0`（`日志/02-w4-green.log`）

| 清理 | `{ removed:["…:s-2"], kept:["…:s-3"] }` | `kept` 一律不得当作已丢弃 |
| 写入器抛错 | `flush` 抛出 `{reason:'quota', message:'本地备份失败：存储空间不足'}`，`pending` 仍为 `true` | 异常不得吞掉后报“已备份”；存储恢复后再次 `flush()` 可补写（实测成功） |

协议字面量 ASCII：本周新增用例含守卫断言（`DRAFT_KEY_PREFIX` 与 8 个落盘字段名均为 ASCII），中文文案不受此限。

```powershell
$root='<包根>\M6_W4_完整包'; $list=[ordered]@{}

$ok=0; $bad=@(); foreach($rel in $list.Keys){
```
