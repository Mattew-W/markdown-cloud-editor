# M6-06 调用样例（交给 M1，可直接复制）

> 全部数值来自实跑 `证据/call_samples.mjs`（原始输出 `日志/08-call-samples.log`），不是示意值。
> 运行方式：`node 证据/call_samples.mjs`（不依赖浏览器；用内存适配器代替 `localStorage`）。

---

## 1. 保存成功

```js
const saved = saveDraft({
  userId, docId, sessionId,
  baseVersion: 3, title: '课程笔记', content: '# 标题\n\n正文', localRevision: 1,
}, storage);
```

真实返回：

```json
{
  "key": "markdown-editor:draft:u-1:d-1:s-1",
  "recordedAt": "2026-11-11T05:42:13.194Z"
}
```

接线规则：

- 界面**只能**显示“已在本地备份”（`SYNC.md` §4.4 文案禁令）。
- **禁止**由此把 `synced` 置 true 或把 `dirty` 置 false：草稿是兜底，自动保存才是主路径。

---

## 2. 保存失败（必须能区分“没写进去”）

```js
try {
  saveDraft(draft, storage);          // storage.setItem 抛 QuotaExceededError
} catch (error) {
  if (error instanceof DraftStorageError) {
    showBackupError(error.message);   // '本地备份失败：存储空间不足'
    keepEditorContent();              // 不清空编辑器
    offerMarkdownDownload();          // SYNC §9.8
  }
}
```

真实抛出：

```json
{
  "name": "DraftStorageError",
  "reason": "quota",
  "message": "本地备份失败：存储空间不足",
  "detail": "QuotaExceededError: quota",
  "isDraftStorageError": true
}
```

- `message` 可直接展示；`detail` 只进日志，**不得**展示（会含浏览器英文原文）。
- **禁止显示“备份成功/已保存”**：磁盘里其实没有这条记录。
- 内存中的内容必须保留，存储恢复后再次 `flush()` 可补写。

---

## 3. 删除被拒绝（`false`）

```js
const ok = discardDraft(key, { sessionId, localRevision: 1, content: '# 标题\n\n正文' }, storage);
```

真实返回（草稿此时已是 `localRevision=9`、`content='更新后的正文'`）：

```json
{
  "returned": false,
  "stillThere": "更新后的正文"
}
```

- 必须保留编辑器内容与 `dirty/synced` 状态，提示“草稿已有新修改，暂不能丢弃”。
- **禁止**把 `false` 当成功去清空编辑器或改状态栏。
- 只有 `sessionId` / `localRevision` / `content` **三项全等**才返回 `true`（`SYNC.md` §9.6）。
- 目标键本不存在时返回 `true`（无可删即已达成目标），调用方不必提示“删除失败”。

## 4. 删除成功（`true`）

```js
const current = readDraft(key, storage);
discardDraft(key, {
  sessionId: current.edit_session_id,
  localRevision: current.local_revision,
  content: current.content,
}, storage);
```

真实返回：

```json
{ "returned": true, "afterDelete": null }
```

## 5. 清理返回 `{ removed, kept }`

```js
const result = clearSessionDrafts(
  { userId, docId, sessionId },                                   // 当前会话
  { cloud: { version: 9, title: '旧标题', content: '已上云' } },     // 云端基准必须三项齐全
  storage,
);
```

真实返回：

```json
{
  "removed": ["markdown-editor:draft:u-1:d-1:s-2"],
  "kept": ["markdown-editor:draft:u-1:d-1:s-3"]
}
```

- `removed` 是“已证实被云端覆盖”的旧会话；`kept` 里有未上云修改，**不得**当作已丢弃。
- `cloud` 缺 `title` 或 `content` 时一律不删（保守，删除不可逆）。
- 不传 `cloud` 也不传 `confirmedKeys` 时一条都不删。
- **顺序**：先 `writer.flush()` 或 `writer.cancel()`，再调用本函数（见 `M1交接表.md` §3）。

## 6. 合并写入器（含失败重试）

```js
const writer = createDraftWriter({ storage, delay, clearDelay });  // delay/clearDelay 成对注入
writer.schedule(draft);   // 窗口内最后一次生效，250ms 到点写一次
writer.flush();           // 切换文档前立即写，并取消待触发定时器
writer.cancel();          // 放弃待写内容，不落盘
writer.flushAll();        // 立即落盘（等价于 flush，保留为兼容入口）
writer.pending();         // 是否仍有待写内容
```

实测三组：

| 场景 | 真实结果 |
|---|---|
| `schedule` → 定时器到点 | `pendingAfterFire=false`，落盘 `["窗口内的最后一次"]` |
| 存储故障时 `flush()` | 抛 `{reason:'quota', message:'本地备份失败：存储空间不足'}`，**`pending` 仍为 `true`** |
| 存储恢复后再次 `flush()` | `pending=false`，落盘 `["存储故障期间的内容"]` |

> 第二组是接线重点：**异常必须冒泡给界面**。若吞掉异常继续显示“备份成功”，用户会以为内容已保存而关闭浏览器——两份都没了。

## 7. 键与身份（防止跨账号串数据）

```json
{
  "key": "markdown-editor:draft:u-1:d-1:s-1",
  "note": "键必须含 userId；M1 传入的 userId 必须是当前账号，切换账号必须重新取会话 ID"
}
```

- 键格式：`markdown-editor:draft:{userId}:{docId}:{sessionId}`，三段 `encodeURIComponent` 编码，`buildDraftKey`/`parseDraftKey` 严格互逆。
- 记录里的 `user_id/doc_id/edit_session_id` 与键不一致 → `corrupt`（实测三种篡改都判 corrupt，且损坏项不会出现在其他账号的 `listDrafts` 里）。
