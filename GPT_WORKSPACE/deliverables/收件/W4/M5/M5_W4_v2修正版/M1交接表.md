# M5 W4 → M1 交接表（UI 输入 / 事件接口）

- 交付角色：M5 前端 UI（刘欣怡 / 24406040124）
- 交接对象：M1 总控（`app.js` 接线）
- 边界：本周**未修改** `app.js / sync.js / api.js / drafts.js`；`ui-feedback.js` 只接收上层传入的状态与错误、把用户选择上抛，不持有第二份文档版本、token 或草稿状态。

## 1. 模块导出（`js/ui-feedback.js`）

| 导出 | 类型 | 说明 |
| --- | --- | --- |
| `SyncState` | 常量枚举 | 七状态字面量：`synced / dirty / saving / retry_wait / auth_required / conflict / invalid`，仅作 UI 文案映射，不复制状态机 |
| `ConflictChoice` | 常量枚举 | `view_cloud / adopt_cloud / save_copy / manual_merge / cancel` |
| `StorageFailureReason` | 常量枚举 | `quota / unavailable / corrupt / serialize` |
| `STORAGE_FAILURE_TEXT` | 冻结文案表 | 四种 reason 的逐字中文文案，禁止透出原始异常 message |
| `stateMeta(state, payload)` | 纯函数 | 返回 `{ badgeClass, badgeText, statusText }` |
| `storageFailureText(reason)` | 纯函数 | 返回冻结文案；未知 reason 回落通用兜底 |
| `errorNotice(error)` | 纯函数 | 按 `code / status` 归类，返回 `{ kind, text }`；不按 `error.message` 分支 |
| `createUiFeedback(elements, callbacks)` | 控制器工厂 | 返回控制器方法集合（见第 3 节） |

## 3. 控制器方法

| 方法 | 入参 | 行为 |
| --- | --- | --- |
| `renderSyncState(state, payload)` | `state` 七状态之一；`payload` 可选 `{ message?, error? }` | 写徽标类名/文案与状态栏；文本经 `textContent` 写入 |
| `showStorageFailure(reason, snapshot)` | `reason` 枚举；`snapshot` 可选 `{ title?, content? }` | 显示冻结文案与下载入口；保留内存内容，不清空编辑器；快照仅由上层传入 |
| `hideStorageFailure()` | — | 隐藏失败条并清空待下载快照 |
| `showConflict(data)` | `{ serverVersion?, localVersion?, cloudContent?, localTitle?, localContent? }` | 只读展示云端版本与本地基准，不替换本地编辑区 |
| `hideConflict()` | — | 关闭冲突弹窗 |
| `getDownloadSnapshot()` | — | 返回当前缓存快照 `{ title, content }` 或 `null`（深拷贝） |
| `destroy()` | — | 移除全部按钮监听，清空上下文与快照（幂等） |

## 4. 上抛回调（`callbacks`，由 M1 接线）

| 回调 | 签名 | 触发时机 |
| --- | --- | --- |
| `onConflictChoice(choice, meta)` | `choice` ∈ `ConflictChoice`；`meta` = `{ serverVersion, localVersion, cloudContent, localTitle, localContent }`（深拷贝） | 用户点击冲突弹窗任一选项；控制器只上抛选择与上下文，不执行覆盖/重载/另存/清草稿 |
| `onDownloadDraft(snapshot)` | `snapshot` = `{ title, content }` 或 `null` | 用户点击“下载当前 Markdown”；文件生成由上层完成 |

## 5. 建议的 M1 接线顺序（本轮未代做）

1. **状态渲染**：在 `sync.js` 的 `onStateChange(state, payload)` 回调内调用 `renderSyncState(state, payload)`。
   - `synced` 仅在 §4.2 三条件全部成立时由上层驱动；`dirty` 只表达“已在本地备份”；`saving` 不宣称已同步。
2. **本地备份失败**：`drafts.js` 写入失败按 reason 调用 `showStorageFailure(reason, { title, content })`；恢复或重试成功后调用 `hideStorageFailure()`。
   - ⚠ **（M1 审计追加，2026-11-11）写入失败时不得宣告「已在本地备份」。**
     `sync.js:117-135` 当前是：草稿写入抛错仅 `console.warn`，随后仍执行
     `setState(SyncState.DIRTY, { …, message: '已在本地备份' })`。存储配额耗尽或
     存储被禁用时，状态栏仍显示「已在本地备份」，与 `docs/SYNC.md` §4.4 文案禁令
     （禁止显示「本地已保存」——草稿实际没存进去）直接冲突，且会与本层的存储失败条
     同时出现在同一屏。
     **要求 M1 在 `drafts.saveDraft` 抛错的分支不驱动 `DIRTY` + `message:'已在本地备份'`**，
     改为仅调用 `showStorageFailure(reason, snapshot)` 且不置 dirty 文案，
     使「本地备份成功」文案与存储成功结果一一对应。
     本层 `stateMeta` 已支持 `payload.message` 覆盖 dirty 文案（`ui-feedback.js:114-115`），
     若 M1 选择保留 dirty 状态但改文案，需保证该文案不含「已备份/已保存」语义。
3. **冲突弹窗**：`onConflict({ serverVersion, localTitle, localContent })` 到达后，结合 `sync.baseVersion`（clientVersion）调用：
   `showConflict({ serverVersion, localVersion: baseVersion, cloudContent, localTitle, localContent })`。
   - 云端只读内容 `cloudContent` 由上层从冲突响应/拉取结果提供。
4. **选择分派**（在 `onConflictChoice` 内，由 M1 决策执行）：
   - `view_cloud`：只读展开云端版本，不改本地内容；
   - `adopt_cloud`：覆盖本地前须保留可恢复草稿；提交时使用读取到的 `serverVersion` 作 `expected_version`，再次冲突继续弹窗；
   - `save_copy`：将本地内容作为新文档 POST；
   - `manual_merge`：停留编辑区由用户合并；
   - `cancel`：控制器已关闭弹窗并保持当前内容，上层不得补发覆盖或清草稿动作。
5. **下载草稿**：`onDownloadDraft` 内由上层生成 Markdown 文件下载；控制器不读取编辑器、不发请求。
6. **错误提示**（M1 审计追加，2026-11-11）：`errorNotice(error)` 是纯函数，本层不写 DOM，
   需由 M1 决定落点。当前可用通道：
   - `errorNotice(err).text` 作为 `payload.message` 传入 `renderSyncState`，用于
     `retry_wait`（429 按传入的 `retryAfter` 展示重试提示）；
   - 或作为 `payload.error` 传入，用于 `invalid`（400 / 413 的字段问题说明）；
   - 401 对应的 `auth_required` **没有** payload 覆盖入口（`ui-feedback.js:80-84` 为固定文案
     「登录已失效，草稿已在本地备份，请重新登录」），已实质满足「提示重新认证」，
     `errorNotice` 的 auth 文本可用于日志 / 埋点，不必上屏。
   - ⚠ `errorNotice` 按 `code / status` 归类（对齐 `docs/INTERFACES.md` C8），
     **不按 `error.message` 分支**，M1 传参时须保证 `code` / `status` / `retryAfter` 字段可用
     （字段名与 `api.js` 一致：`status` / `code` / `retryAfter` / `serverVersion`）。

## 7. 本层明确不做（防副本规则）

- 不发 `PUT / POST` 请求，不直接保存；
- 不自增 `expected_version / version`；
- 不清除草稿、不替换编辑器文本；
- 不维护第二份 `currentDocument`、token 或本地存储访问；
- 面向用户文本一律 `textContent`，不用 `innerHTML` 拼接用户或服务端文本。
