### 🟡 D3 `javascript:` 链接的机制描述与截图 07 不符

**记录称**（`检查记录.md:35`）：「`javascript:` 链接被净化，href 移除，仅保留链接文字"点我"」

**截图 07 实际**：预览区显示**破图图标 + 纯文本** `[点我](javascript:alert(1))`（含方括号与完整 scheme），**根本没有生成 `<a>` 元素**，不存在"href 被移除"这一步。

**机制实测**（我用官方 marked 12.0.2 复现）：

| 场景 | marked.parse 输出 |
| --- | --- |
| 三行连续输入（与截图 07 一致） | `"<img src=x onerror=alert(1)>\n[点我](javascript:alert(1))\n<script>alert(2)</script>"` —— 以 `<img …>` 开头触发 CommonMark **HTML block，整块原样透传**，链接从未被解析 |
| 链接单独成行 | `"<p><a href=\"javascript:alert(1)\">点我</a></p>\n"` —— 此时 DOMPurify 才剥离 href |

**影响**：安全结论**依然成立**（无弹窗、无脚本执行、无危险节点），且该净化路径在单测 `tests/editor.security.test.js:77-96`（链接单独成行）中被有效覆盖。问题在于记录把「单测里成立的行为」写成了「浏览器实测到的行为」，掩盖了"浏览器端该输入从未被解析为链接"这一事实。

**改法**：`检查记录.md:35` 改为：「三行连续输入使 marked 将其整体识别为 HTML block 透传，故预览区显示 `[点我](javascript:alert(1))` **纯文本**（无 `<a>`、无 href、不可点击）；`<img>` 的 `onerror` 被 DOMPurify 剥离后仅剩破图占位；`<script>` 整段连内容一并移除。`javascript:` href 的剥离路径由 `tests/editor.security.test.js:77-96` 在链接单独成行时覆盖。」

### package.json 合并要点（不可覆盖）

主仓库现为 `name: markdown-cloud-editor-frontend`，scripts 有 `test` / `test:api` / `test:drafts` / `test:log` 四个。**直接用本包覆盖会丢失 M6 的 `test:api`/`test:drafts`/`test:log`。** 合并应：

1. 保留主仓库 `name` / `version` / 四个 scripts / `engines`
2. 追加 `devDependencies`: `marked@12.0.2`、`dompurify@3.3.3`、`jsdom@30.1.3`
3. `test` 脚本需同时覆盖两处测试目录。本包实测发现**裸 `node --test` 在 Windows 上 `node --test tests/` 会报 `Cannot find module`**（已复现），主仓库现为 `node --test "js/tests/*.test.js"`——合并后建议双 glob，但需实测确认 Node 对 glob 的支持
4. **`engines` 必须收紧**：jsdom 30.1.3 的 `engines.node` 为 `^22.22.2 || ^24.15.0 || >=26.0.0`，而主仓库现声明 `>=22.0.0`——合并后 22.0.0~22.22.1 区间装不上 jsdom

### ⚠ `demo.js` 不宜原样迁入生产目录

### M5 / M6 边界

**功能无重叠**：M5 `editor.js` 只碰 DOM；M6 `drafts.js` 是零 DOM 纯逻辑草稿层（七个 export 全为逻辑/存储函数）。存储所有权无冲突（M5 全程零存储访问）。草稿能力**未重复实现**——M6 已有 `saveDraft/readDraft/...`，M5 只做 UI 级 `beforeunload`/`confirm` 保护（交互提示 vs 数据落盘，语义不重叠）。

**接口同名不同源需注意**：`INTERFACES.md:409` 的 C7 `onInput` 是「sync → 界面」方向的能力清单（且规定每次 +1 `local_revision`）；本包 `onInput(callback)` 是「界面 → 订阅者」方向的订阅 API。联调时须明确谁是订阅方、谁负责 `local_revision` 自增。

**方向正确**：`ARCHITECTURE.md:127` 规定 `local_revision` 归 `sync.js`，故 `editor.js` **不应自行计数**——本包 `js/editor.js` 恰好没有计数，实现方向正确。

`ARCHITECTURE.md:129`「预览 HTML 归 editor.js，不外传」成立——`getValue()` 只返回原始 `{title, content}` 字符串，不返回渲染后的 HTML。

## 7. 总体评价

**这是一份值得认可的交付。** 与 W1 相比，M5 在三个维度上有明显进步：

1. **从"演示脚本"到"可复用模块"**：`editor.js` 零 import、零全局、依赖注入、参数校验、幂等 destroy——这是工程化的写法，不是作业写法。
2. **安全基线从"概念"到"实测"**：真实 marked 12.0.2 + 真实 DOMPurify 3.3.3 本地托管（SHA256 与官方字节级一致），8 个安全测试用 jsdom 真实 DOM 断言 DOM 结果而非"函数被调用"。
3. **诚实度显著提升**：`阶段记录.md` 主动记录了首次启动失败（沙箱未监听 → ERR_CONNECTION_REFUSED）和依赖下载受阻（curl SSL 失败 → 改走 npm pack），并列出 4 条明确未执行项。这与 W1 时"已知问题：无"形成鲜明对比。

**W1 遗留的 `.repeat(20)` 作用域 bug 已正确修复**（`js/demo.js:23` 现在 repeat 只作用于填充段落，标题为独立字面量），且本轮我没有再发现任何代码级缺陷。

需要指出的三处都是**记录表述与证据对不齐**，技术实现本身没问题。这说明 M5 的短板已从"代码"转移到"观察描述的精确性"——这恰恰是可以通过复核清单快速改善的。建议在 W3 继续要求：每条实测记录必须与对应截图的**具体像素事实**对齐，机制描述必须区分"浏览器实际观察到的"与"单元测试覆盖的"。
