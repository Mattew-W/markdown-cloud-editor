## 四、M3 W2 集成技术说明

### 4.1 修复一：TTL 计算溢出 panic（M3 原始修复）

**问题**：`token.rs` 原代码使用 `Duration::seconds(ttl_secs as i64)` 直接强转，当 `ttl_secs` 超过 `i64::MAX` 时发生算术溢出 panic，属于可触发的生产级崩溃路径。

**M3 修复**（`chrono::Duration::seconds`）已将乘法移至 chrono 内部，但 M1 进一步将其升级为 `Duration::try_seconds(ttl_secs as i64).ok_or(TokenError::InvalidTtl)?`，在极端值（如 `u64::MAX`）时优雅返回错误而非 panic，保证符合项目 `#![forbid(unsafe_code)]` 与"外部输入不使用 unwrap"的代码规范。

### 4.2 修复二：空 `sub` 绕过鉴权（M3 原始修复）

**问题**：`decode_token` 在 Claims 验证时未拒绝 `sub = ""`，攻击者可伪造空用户名令牌通过鉴权层。

**M3 修复**：在 decode 路径增加 `if claims.sub.is_empty() { return Err(...) }` 检查。M1 已全量采纳并通过 CR。

### 4.3 新增边界测试（6 条）

| 测试名 | 贡献方 | 覆盖场景 |
|--------|--------|----------|
| `test_empty_sub_rejected` | M3 | `sub=""` 令牌被拒绝 |
| `test_expired_token_rejected` | M3 | 已过期令牌被拒绝 |
| `test_wrong_secret_rejected` | M3 | 签名密钥不匹配 |
| `test_malformed_token_rejected` | M3 | 格式非法令牌 |
| `test_zero_ttl_rejected` | M3 | TTL=0 令牌立即过期 |
| `test_i64_max_ttl_hardened` | **M1** | `ttl=i64::MAX` 不 panic，返回 `TokenError::InvalidTtl` |
