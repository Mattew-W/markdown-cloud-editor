### 四个致命缺陷

| # | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| 1 | **U+2011 非断行连字符** | `api.js:100/138/168` | `TypeError: ...value of 8209`，所有请求在构造 header 阶段即崩，一个都发不出去 |
| 2 | **`node:test` 导入不存在的 `assert`** | `api.test.js:1` | 23 个用例全部 `assert.deepEqual is not a function` |
| 3 | **URL 构造发往不存在外域** | `api.js:80` | `new URL(path, 'http://dummy-base')` → 实测 `ERR_NAME_NOT_RESOLVED`，真实后端永远收不到请求 |
| 4 | **Content-Type 正则漏 `+json`** | `api.js:140` | `application/vnd.api+json` 不匹配，协议明确要求支持 |

缺陷 1、2 在语法检查下完全合法（`node --check` 通过），**只有真跑才暴露**。

> 缺陷 3 值得注意：原测试 `assert.equal(input.pathname, ...)` 之所以"看起来对"，是因为 mock fetch 拿到 URL 对象、`.pathname` 恰好正确——**测试写法掩盖了真实缺陷**。这正是「Mock 不得访问真实后端」条款的盲区。

### 应予肯定

零 DOM、接口签名与任务书完全一致、九类错误码零偏差、两种 409 未混淆、`serverVersion` 不编造、204 不调 `json()`、按 code 而非 message 分支、不自动重试、错误不暴露 HTML、定时器 finally 清理。

交付说明三问的作答**质量不错**，尤其第三问（超时为何不能断言服务器一定没保存）的答案准确，符合规范 §08「结果未知」语义。**返工应保留现有设计，只修实现缺陷。**
