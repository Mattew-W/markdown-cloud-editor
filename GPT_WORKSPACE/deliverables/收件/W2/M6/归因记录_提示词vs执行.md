# M6 W2 归因记录：提示词 vs 执行

**日期**：2026-10-26　**收件**：`M6_W2_吴泽佳2026.10.26.zip`　**结论**：**提示词合格，失败在执行与证据链**

本记录用于回答「我的描述词没问题吧？怎么这么差」，并作为 W2 收件的归因依据。方法：把 W2 提示词原文与交件代码逐条对照。

---

## 一、四个致命缺陷的归因

| 缺陷 | 提示词是否已写明 | 判定 |
|---|---|---|
| 1. U+2011 连字符污染 | **未提及**（无「ASCII」「连字符」「全角」等表述） | **提示词真实缺口** |
| 2. `node:test` 导入不存在的 `assert` | 提到 `assert`，未指明来自 `node:assert` | 执行方问题（Node 基础 API） |
| 3. URL 构造发往 `dummy-base` | **已写明**「path是单个/开头的相对路径，禁止完整外域URL…统一拼接一次」 | 执行方问题（直接违反） |
| 4. Content-Type 正则漏 `+json` | **已写明**「支持application/json及application/*+json（忽略参数和大小写）」 | 执行方问题（直接违反） |

**三个是直接违反已写明的约束**，且违反点在「本阶段必须保留的约定」段落中每段重复出现。

## 三、真正的根因：证据链无强制力

W1 与 W2 失败同构：

| | W1 | W2 |
|---|---|---|
| 功能实现 | 大部分正确 | 设计零缺陷（九类 error.code 与冻结 API.md 9/9 一致） |
| 记录与交付物 | 「未执行项：无」但两项未测 | 「pass 1 / fail 0」而实际 0/23 |
| 占位/错配 | 浏览器版本占位符 | 把不属于本交件的输出填进记录 |

提示词里针对此事的六条防作弊条款——「通过数量由真实runner输出决定」「保存真实输出」「不能只有console.log」「不删除测试来凑通过」「不能用模板」「不预填」——**全部命中，一条未执行**。

> 23 个用例全部因 `assert.deepEqual is not a function` 失败，任何一次真实执行都会立刻暴露。交件成立唯一原因是那段输出不是跑出来的。

**提示词能约束「怎么写代码」，约束不了「有没有真的按下运行键」。**

## 四、后续动作

### 4.1 提示词层：补协议字面量的 ASCII 校验

对应缺陷 1。U+2011 语法合法、`node --check` 通过、视觉近似 ASCII，但在 HTTP 头名场景下直接抛 `TypeError`。

建议加入通用生成流程第 6 条：

> **协议字面量必须逐字节核对**：HTTP 头名、字段名、Content-Type、错误码枚举等会被程序按精确字符串匹配的标识符，必须是纯 ASCII。写完后扫描非 ASCII 字符，确认只出现在注释与文案里。
>
> ```sh
> grep -nP '[^\x00-\x7F]' js/*.js | grep -v '^\s*[0-9]*:\s*//'
> ```

适用范围不止 M6——M2 的 SQL、M4 的字段名、M5 的 DOM 选择器均有同类风险。

### 4.2 机制层（优先级更高）：把「跑没跑」变成硬门禁

继续加提示词条款的边际收益在下降。建议改用机制：

| 方案 | 做法 | 拦截能力 |
|---|---|---|
| A（推荐） | 交付前跑真实 runner，抽取计数与检查记录数字机器比对，不一致直接拒收 | 100% 拦住本次事件 |
| B | 交付原始日志文件 + sha256，交接时校验 | 粘贴片段可编，原始日志难编 |
| C | 阶段记录加必填「实际执行环境：有终端已自执行 / 无终端已给步骤等用户执行」 | 明确无权限时由用户执行，AI 不猜输出 |

## 五、归因总结

| 层面 | 结论 |
|---|---|
| 提示词质量 | **合格，属这批里最扎实**（7 条 M6-R 规则逐条对应 W1 真实遗漏） |
| 提示词唯一缺口 | 协议字面量 ASCII 校验（缺陷 1） |
| 执行方问题 | 缺陷 2/3/4 均为直接违反已写明约束 |
| 机制问题 | **规则无强制力（根因）**——W1/W2 两次同构失败 |
| AI 品牌 | **不能归因**——M3、M5 同用豆包，验证达标率 83.3% vs 28.6% |
