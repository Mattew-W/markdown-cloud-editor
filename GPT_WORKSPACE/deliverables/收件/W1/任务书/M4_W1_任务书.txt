# M4｜本周本地任务：文档输入校验小程序

时间：2026-10-19 至 10-25。10-25 晚交给 M1；如果做不完，交已有文件和问题记录。
项目背景：六人合作做 Rust 后端、PostgreSQL 数据库、原生网页前端的云同步 Markdown 编辑器。你本周只完成下面这个小练习，M1 负责最后接入项目。

## 怎么开始

在自己电脑上建立 M4_W1 文件夹，用支持编辑文件的 AI 编程工具打开它。无需 GitHub、Git、分支或 PR；无需下载完整项目。这是一份完整任务说明，不依赖其他文档。已有文件先保留，不覆盖旧作业。

本周目标：做一个独立 Rust 小程序，判断标题和正文输入是否符合给定规则。

## 按顺序做

1. 新建 M4_W1 文件夹。检查 rustc 和 cargo；让 AI 建一个名为 validation_demo 的 Cargo 小项目。

2. 本周练习规则：标题去掉首尾空白，空标题变成“未命名文档”；标题最多 100 个 Unicode 字符（Rust chars().count()）；正文允许空，最多 100000 个 UTF-8 字节。以上是练习参数，正式项目由 M1 审定。

3. 实现一个纯函数，输入标题、正文，返回整理后的标题或明确错误。不连接数据库，不写 HTTP，也不处理权限、版本或并发。

4. 在 main 中准备示例：正常中文标题、全空格标题、100 字标题、101 字标题、空正文、正文恰好上限和超过上限。超长内容在程序中生成，不手写巨大文本。

5. 运行 cargo run，记录每种输入的结果；请 AI 解释字符数与字节数为什么不同。把规则集中为常量，方便 M1 后续修改。

## 要交哪些文件

| 文件 | 内容 |
|---|---|
| `validation_demo/Cargo.toml` | 独立小程序配置 |
| `validation_demo/Cargo.lock` | 实际生成的锁文件 |
| `validation_demo/src/main.rs` | 校验函数和运行示例 |
| `检查记录.md` | 七类输入的预期、实际结果和待确认问题 |
| `交付说明.txt` | 姓名/编号、完成项、打开或运行方法、没完成的地方、使用了哪些 AI |

## 怎么证明完成

正常输入能通过，越界输入能给出可读错误；你能指出规则常量和校验函数在哪里。

自己打开或运行一次，能花两分钟说明“做了什么、从哪里运行、还有什么没做好”。检查记录写真实命令、操作、结果及错误；未运行就写未运行。AI 生成代码不等于检查通过。

## 怎么交给 M1

1. 把源文件、运行配置、依赖锁文件、说明和必要截图放进 M4_W1 文件夹。
2. 不放 target、node_modules、.git、真实 .env、密钥、账号密码或个人资料。锁文件若因依赖下载失败没有生成，在说明里写明。
3. 压缩为 M4_W1_姓名_20261025.zip，通过你们平时聊天或传文件的方式交给 M1。返工时另加 v2、v3，不覆盖自己上一版。
4. 下周等待 M1 检查本次成果后发新任务；不要自行照旧 W2 预案往下做。
