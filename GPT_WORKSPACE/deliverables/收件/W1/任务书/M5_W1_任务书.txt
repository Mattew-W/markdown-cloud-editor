# M5｜本周本地任务：编辑器静态页面

时间：2026-10-19 至 10-25。10-25 晚交给 M1；如果做不完，交已有文件和问题记录。
项目背景：六人合作做 Rust 后端、PostgreSQL 数据库、原生网页前端的云同步 Markdown 编辑器。你本周只完成下面这个小练习，M1 负责最后接入项目。

## 怎么开始

在自己电脑上建立 M5_W1 文件夹，用支持编辑文件的 AI 编程工具打开它。无需 GitHub、Git、分支或 PR；无需下载完整项目。这是一份完整任务说明，不依赖其他文档。已有文件先保留，不覆盖旧作业。

本周目标：做一个能在浏览器打开的 Markdown 编辑器页面外观。

## 按顺序做

1. 新建 M5_W1 文件夹，里面建 index.html、style.css、demo.js。用原生 HTML/CSS/JavaScript，不安装前端框架。

2. 页面包括：左侧文档列表、中间标题和正文输入框、右侧预览占位区、顶部保存按钮、底部状态提示。使用三篇写明“演示数据”的虚构文档。

3. 点击不同演示文档可看到对应标题和正文；本周可以只显示演示内容，提示切换会重置未保存的编辑。保存按钮只提示“演示模式，尚未接入保存”。

4. 预览区本周先用 textContent 显示正文原文，标注“Markdown 渲染待接入”；不要把输入直接插入 innerHTML。无需登录、网络请求或云同步。

5. 双击 index.html 打开，测试中文输入、长标题、窗口变窄和滚动；记录浏览器名称。截一张页面图，并解释每个文件负责什么。

## 怎么证明完成

无需服务器即可打开，布局能看清，按钮不假装保存成功；输入内容不会当作 HTML 执行。

自己打开或运行一次，能花两分钟说明“做了什么、从哪里运行、还有什么没做好”。检查记录写真实命令、操作、结果及错误；未运行就写未运行。AI 生成代码不等于检查通过。

## 怎么交给 M1

1. 把源文件、运行配置、依赖锁文件、说明和必要截图放进 M5_W1 文件夹。
2. 不放 target、node_modules、.git、真实 .env、密钥、账号密码或个人资料。锁文件若因依赖下载失败没有生成，在说明里写明。
3. 压缩为 M5_W1_姓名_20261025.zip，通过你们平时聊天或传文件的方式交给 M1。返工时另加 v2、v3，不覆盖自己上一版。
4. 下周等待 M1 检查本次成果后发新任务；不要自行照旧 W2 预案往下做。
