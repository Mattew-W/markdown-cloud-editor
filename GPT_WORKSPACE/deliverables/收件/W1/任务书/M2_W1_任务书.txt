# M2｜本周本地任务：数据库字段和 SQL 草稿

时间：2026-10-19 至 10-25。10-25 晚交给 M1；如果做不完，交已有文件和问题记录。
项目背景：六人合作做 Rust 后端、PostgreSQL 数据库、原生网页前端的云同步 Markdown 编辑器。你本周只完成下面这个小练习，M1 负责最后接入项目。

## 怎么开始

在自己电脑上建立 M2_W1 文件夹，用支持编辑文件的 AI 编程工具打开它。无需 GitHub、Git、分支或 PR；无需下载完整项目。这是一份完整任务说明，不依赖其他文档。已有文件先保留，不覆盖旧作业。

本周目标：用普通文字说明用户和文档需要存什么，再让 AI 写建表 SQL 草稿。

## 按顺序做

1. 新建 M2_W1 文件夹，用 VS Code 或记事本编辑。已有 PostgreSQL 可以使用；安装卡住就记录问题，先完成文档和 SQL 草稿。

2. 写两个表的字段表。users：id、username、password_hash、created_at；documents：id、owner_id、title、content、version、created_at、updated_at。每个字段写用途、建议类型、是否必填。id 类型、长度和默认值是建议，留给 M1 最终确认。

3. 用通俗话解释：用户名不能重复；每篇文档属于一个用户；密码只存哈希；version 表示保存版本。写两条虚构用户和文档示例，勿使用真实账号资料。

4. 让 AI 根据字段表写 PostgreSQL 建表草稿，包含主键、唯一用户名、用户关联和正数版本约束。不要写后端查询、接口或 Rust 数据模型。

5. 如果本机有独立练习数据库，可以运行 SQL，尝试重复用户名和不存在的 owner_id。仅在练习库操作；没有环境就写“未执行”，交给 M1 检查。

## 要交哪些文件

| 文件 | 内容 |
|---|---|
| `字段说明.md` | 两个表的字段、示例、关联和待确认问题 |
| `schema-draft.sql` | 创建 users/documents 的 SQL 草稿 |
| `检查记录.md` | 实际执行结果，或环境问题与未执行项 |
| `交付说明.txt` | 姓名/编号、完成项、打开或运行方法、没完成的地方、使用了哪些 AI |

## 怎么证明完成

你能用自己的话解释 owner_id 和 version；SQL 草稿与字段表一致。运行过才写“已验证”，只写 SQL 不代表数据库检查通过。

自己打开或运行一次，能花两分钟说明“做了什么、从哪里运行、还有什么没做好”。检查记录写真实命令、操作、结果及错误；未运行就写未运行。AI 生成代码不等于检查通过。

## 怎么交给 M1

1. 把源文件、运行配置、依赖锁文件、说明和必要截图放进 M2_W1 文件夹。
2. 不放 target、node_modules、.git、真实 .env、密钥、账号密码或个人资料。锁文件若因依赖下载失败没有生成，在说明里写明。
3. 压缩为 M2_W1_姓名_20261025.zip，通过你们平时聊天或传文件的方式交给 M1。返工时另加 v2、v3，不覆盖自己上一版。
4. 下周等待 M1 检查本次成果后发新任务；不要自行照旧 W2 预案往下做。
