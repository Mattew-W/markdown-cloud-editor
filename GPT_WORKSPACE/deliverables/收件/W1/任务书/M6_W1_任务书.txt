# M6｜本周本地任务：浏览器本地草稿演示

时间：2026-10-19 至 10-25。10-25 晚交给 M1；如果做不完，交已有文件和问题记录。
项目背景：六人合作做 Rust 后端、PostgreSQL 数据库、原生网页前端的云同步 Markdown 编辑器。你本周只完成下面这个小练习，M1 负责最后接入项目。

## 怎么开始

在自己电脑上建立 M6_W1 文件夹，用支持编辑文件的 AI 编程工具打开它。无需 GitHub、Git、分支或 PR；无需下载完整项目。这是一份完整任务说明，不依赖其他文档。已有文件先保留，不覆盖旧作业。

本周目标：做一个小页面，把输入内容暂存在当前浏览器，刷新后可手动恢复。

## 按顺序做

1. 新建 M6_W1 文件夹，建 index.html 和 drafts.js。使用原生 JavaScript 和 localStorage，不需要后端或数据库。

2. 页面放一个文本输入区，以及“保存到本机”“读取本机草稿”“清除本机草稿”三个按钮。使用独立键 markdown-editor-demo:M6:W1，不调用 localStorage.clear()。

3. 保存正文和保存时间；点击读取才把草稿放回输入区。已有未保存输入时先提示确认，避免覆盖。没有草稿时提示“暂无本机草稿”。

4. 处理存储不可用、空间不足、保存内容格式损坏的错误，显示提示，不让页面崩溃。页面明确写“只保存在当前浏览器，不是云同步”；不保存密码或 token。

5. 测试中文输入、刷新后读取、清除后读取、损坏内容。可双击打开；若浏览器限制 file 地址存储，使用编辑器本地静态服务器并记录地址和启动方法。本周不用做自动保存、API client 或冲突处理。

## 要交哪些文件

| 文件 | 内容 |

| `index.html` | 可独立打开的草稿演示页 |

## 怎么证明完成

同一浏览器和同一地址下能演示保存、刷新、手动读取与清除；明白换设备不会得到本机草稿。

自己打开或运行一次，能花两分钟说明“做了什么、从哪里运行、还有什么没做好”。检查记录写真实命令、操作、结果及错误；未运行就写未运行。AI 生成代码不等于检查通过。

## 怎么交给 M1

1. 把源文件、运行配置、依赖锁文件、说明和必要截图放进 M6_W1 文件夹。
2. 不放 target、node_modules、.git、真实 .env、密钥、账号密码或个人资料。锁文件若因依赖下载失败没有生成，在说明里写明。
3. 压缩为 M6_W1_姓名_20261025.zip，通过你们平时聊天或传文件的方式交给 M1。返工时另加 v2、v3，不覆盖自己上一版。
4. 下周等待 M1 检查本次成果后发新任务；不要自行照旧 W2 预案往下做。
