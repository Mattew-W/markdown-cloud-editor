## 一、返工包 `_v2` —— 修了什么

对应 `M6_W1_审核记录.md` 第四节的 F2/F3/F4/F5/F6/F7/F10。

| 编号 | 原问题 | 修法 | 位置 |
|---|---|---|---|
| F7 | 无 export，无法被 `<script type="module">` 具名导入 | 补 `export { saveDraft, loadDraft, clearDraft, describeStorageError, parseDraft }` | `drafts.js` 末尾 |
| F2 | SecurityError 在保存/清除路径走 else 分支，暴露浏览器原始英文 `The operation is insecure.` | 抽 `describeStorageError()` 统一分类，三条路径共用 | `drafts.js:36-52` |
| F3 | JSON.parse 成功但 content 非字符串时被静默接受；savedAt 缺失仍显示「Invalid Date」 | 抽 `parseDraft()` 校验结构，`content` 非字符串或 `savedAt` 非有限数一律判损坏 | `drafts.js:57-82` |
| F4 | confirm 在检查草稿存在性之前弹出，无草稿也让用户确认「会覆盖」 | 先 `getItem` 判存在性，无草稿直接提示并返回 | `drafts.js:100-106` |
| F5 | confirm 取消后直接 return，msg 停留旧的「✅读取成功」，用户误判 | 取消时提示「已取消读取，输入框内容未变」 | `drafts.js:110-115` |
| F6 | `trim()` 判空导致纯空白输入不触发覆盖确认 | 改用 `value !== ""` | `drafts.js:109` |
| F10 | 三个 button 无 `type` 属性，DOM 默认 `submit` | 显式 `type="button"` | `index.html:14-16` |

**附带修正的两处文案问题**（原文案违反规范 §08:349「本地备份成功不能显示成云端保存成功」）：

- `✅保存成功，保存时间：…` → `✅已备份到本机（仅本机，非云同步），保存时间：…`
- `✅读取成功，上次保存：…` → `✅已读取本机草稿，上次保存：…`

### 实测结果

真实 headless Chromium 149.0.7827.55，异常用 `addInitScript` 注入**原生 DOMException**（非 mock DOM、非手写假错误类）。

```
node verify_v2.js

总计 15 项，通过 15，失败 0
```

覆盖：ES Module 具名导入、保存文案区分本地/云端、存储内容字段、刷新后读取、无草稿不弹确认、有草稿弹确认、取消读取提示明确、纯空白也触发确认、8 种损坏输入全部走损坏分支、存储不可用三路径中文文案、配额耗尽不崩溃、三个按钮 type 属性、中文+emoji 往返无损。

### ⚠️ 一处必须知道的副作用：file:// 双击打开会失效

`index.html` 改用了 `<script type="module">`——这是 F7 修复的必要条件，因为 ES Module 必须以 module 方式加载。

**代价：file:// 协议下浏览器会以 CORS 策略拦截 module 脚本，页面白屏。**

已实测确认，不是推测：

```
node verify_file_protocol.js

console.error: Access to script at 'file:///.../drafts.js' from origin 'null'
has been blocked by CORS policy: Cross origin requests are only supported for
protocol schemes: chrome, chrome-untrusted, data, http, https.
  | Failed to load resource: net::ERR_FAILED

结论：file:// 下返工包 v2 不可用（模块未执行）
```

**这不是可以两全的取舍。** 曾尝试做一个"双击打开版"页面（module 加载失败时回退到 classic script 注入），但那需要维护一份去掉 export 的重复副本——正是审核记录 §4 所指的"不一致副本"温床，与本次返工的目标相悖，故放弃该方案。

**实际影响为零**：组员原检查记录里用的就是 `python3 -m http.server 9000`，运行方式没有变化。

```sh
python -m http.server 9000 --bind 127.0.0.1
# 浏览器访问 http://127.0.0.1:9000/index.html
```

## 二、正式模块草案 `正式模块草案_frontend/`

按项目规范 §08 与契约 C1–C6 重写。**这是能进主项目的版本。**

### 设计原则

1. **零 DOM** — 不引用 `document` / `window` / `textarea`，全部通过参数接收输入
2. **存储可注入** — 经注入的 `storage` 对象访问，使测试能可靠模拟存储禁用/配额耗尽/值损坏
3. **身份不内置** — `userId` 一律由调用方传入，不读 token、不持有全局身份副本
4. **错误不外泄** — 统一 `DraftStorageError`，用 `reason` 区分原因，不透传 `e.message`
5. **草稿是兜底** — 任何成功返回都不代表云端已保存，调用方不得据此改变 synced/dirty 判定

### 导出接口

| 函数 | 用途 |
|---|---|
| `createEditSessionId()` | 生成编辑会话 ID（`crypto.randomUUID()`） |
| `buildDraftKey({userId,docId,sessionId})` | 构造三元组键 |
| `parseDraftKey(key)` / `isDraftKey(key)` | 解析与判定草稿键 |
| `saveDraft(record, {storage,now})` | 写入草稿，`recorded_at` 由模块盖 ISO 8601 戳 |
| `readDraft(key, {storage})` | 读取，返回 `{status:'ok'\|'missing'\|'corrupt'}` |
| `listDrafts({userId,docId}, {storage})` | 枚举遗留草稿，损坏项计入 `corrupt` 不抛出 |
| `discardDraft(key, {sessionId,localRevision,content}, {storage})` | 三重核对后删除，不匹配返回 `mismatch` |
| `clearSessionDrafts(sessionId, {userId}, {storage})` | 按会话精确清理，不跨会话不跨账号 |
| `createDraftWriter({storage,now,delay})` | 250ms 合并写入调度器，提供 `schedule/flush/flushAll/cancel/pending` |
| `classifyRestore(draft, cloud)` | 恢复三分支判定，返回 `identical/confirm/conflict/unavailable` |
| `isValidDraftRecord(record)` | 草稿记录结构校验 |
| `byteLength(text)` | UTF-8 字节数 |

### 测试

```sh
cd 正式模块草案_frontend
node --test "tests/unit/drafts.test.js"
```

**实测结果：40 项测试，9 个套件，40 通过 / 0 失败**，耗时 237ms。

覆盖：键生成与解析（含分隔符转义）、user/doc 隔离、多会话并存、枚举时间倒序、损坏项不抛出、清理三重核对拒绝误删、按会话清理不跨账号、quota/unavailable/corrupt 三类错误、错误文案不含原始英文、250ms 合并写入（用可控时钟，不依赖真实等待）、flush/flushAll/cancel、恢复三分支判定。

### 与 W1 练习稿的差距

| 维度 | W1 稿 | 正式模块草案 |
|---|---|---|
| 存储键 | 单一固定键 | 三元组 `markdown-editor:draft:{userId}:{docId}:{sessionId}` |
| 记录字段 | `content` + `savedAt` | 八字段（含 `base_version`/`title`/`local_revision`） |
| DOM 耦合 | 直接操作 textarea | 零 DOM |
| 模块形式 | 普通脚本 | ES Module，具名导出 |
| 错误处理 | 三条路径三种文案 | 统一 `DraftStorageError{reason}` |
| 遗留草稿 | 无法枚举 | `listDrafts()` |
| 恢复判定 | 无 | `classifyRestore()` 三分支 |
| 清理 | 直接 `removeItem` | 三重核对（会话+修订号+内容） |
| 合并写入 | 无 | 250ms 合并调度器 |
| 单元测试 | 无 | 40 项 |
