二、修了什么
═══════════════════════════════════════════════

F2  存储异常统一中文文案
    之前保存/清除路径遇到 SecurityError 会直接显示浏览器原始英文
    "The operation is insecure."，读取路径却显示中文，三条路径不一致。
    现在抽出 describeStorageError() 统一分类。

F3  草稿内容结构校验
    之前只 catch JSON.parse 的语法错误。实际写入合法 JSON 但结构不符时
    （如 content 是数字、对象，savedAt 缺失）会被静默接受，
    文本框里出现 "123" 或 "[object Object]"，
    时间显示成 "Invalid Date" 却仍提示"读取成功"。
    现在抽出 parseDraft() 校验 content 与 savedAt，不符一律判损坏。

F4  覆盖确认的时机
    之前 confirm 在检查草稿是否存在之前就弹，没草稿也让用户确认"会覆盖"。
    现在先判断草稿存在，再决定是否确认。

F5  取消读取的反馈
    之前点取消后直接 return，页面提示停留在上一次的"✅读取成功"，用户会误判。
    现在明确提示"已取消读取，输入框内容未变"。

F6  纯空白输入
    之前用 trim() 判空，输入框只有空格时点读取不弹确认。
    现在改为直接判空值。

F7  补 export
    之前没有 export，无法被 <script type="module"> 具名导入。
    现在补上 export，可被具名导入。

F10 按钮 type 属性
    之前三个 button 没有 type，DOM 中默认是 submit，嵌入表单会意外提交。
    现在显式写 type="button"。

另外改了两处文案（原文案违反项目规范 §08:349
"本地备份成功不能显示成云端保存成功"）：

  "✅保存成功，保存时间：…"
    → "✅已备份到本机（仅本机，非云同步），保存时间：…"

  "✅读取成功，上次保存：…"
    → "✅已读取本机草稿，上次保存：…"

三、怎么运行
═══════════════════════════════════════════════

必须用本地静态服务器打开，不能双击 file:// 地址。

  cd M6_W1_v2
  python -m http.server 9000 --bind 127.0.0.1
  浏览器访问 http://127.0.0.1:9000/index.html

为什么不能双击：
drafts.js 补了 export 后必须是 ES Module，浏览器在 file:// 协议下
会以 CORS 策略拦截 module 脚本，页面会白屏并报
"blocked by CORS policy"。这在浏览器里直接打开时是看不到具体原因的，
所以改用静态服务器。

你的原检查记录里本来就用的 python3 -m http.server 9000，
运行方式没有变化。

四、没完成的地方
═══════════════════════════════════════════════

本版仍然是"本机 localStorage 演示"，不是云同步。以下都没做，
它们属于正式项目范畴（见项目规范 §08）：

  - 草稿键仍是单一固定键，不含 user_id / doc_id / edit_session_id
  - 草稿记录仍只有 content 与 savedAt，缺 base_version / title / local_revision
  - 仍直接操作 DOM，正式项目的 drafts.js 应是零 DOM 纯逻辑层
  - 没有自动保存、没有 API client、没有冲突处理
  - 没有单元测试

首版审核记录的结论是：这份代码作为练习合格，
但作为正式项目的 frontend/js/drafts.js 须重写。
下一周会按新契约重写，本版只作为练习存档。
