## 3. 相对原始交付的修正点（代码级）

| 审计编号 | 问题 | 修正方式 |
| --- | --- | --- |
| F5 | 正文超限返回 400（契约规定 413）；`PayloadTooLarge`/`Internal` 从未被构造 | 新增 `From<ValidationError>`：`ContentTooLarge` → `PayloadTooLarge`；create/update 两条路径均经此翻译 |
| F6 | update 路径未持久化 trim 后标题 | `UpdateDocumentRequest::validate()` 改为返回 trim 后标题，service 将其传入仓储 |
| F7b | 无稳定错误码 | 新增 `DocumentServiceError::code()`，产出 API.md §4.1 的 5 个稳定字面量 |
| F8 | 响应类型命名/时间戳精度/缺 `DeleteDocumentQuery`/派生缺失/thiserror v1 | 更名为 `UpdateDocumentResponse`；时间戳改 `String` 并经 `format_timestamp()` 输出秒级 RFC 3339；补 `DeleteDocumentQuery`；派生对齐主仓库；thiserror 升 v2 |
| F9 | 仓储错误类型倒置不彻底 | 新增 `RepositoryError`（Connection/Constraint/Timeout），trait 改返回它，service 经 `#[from]` 包装为 `Internal` |
| F10 | main.rs 为 Hello-world 桩 | 重写为内存仓储演示，19 个场景，失败即非零退出 |
| F4b（lint 部分） | 模拟合入触发 63 个 lint 错误 | lib.rs 内置主 crate lint 头并补齐全部公开项文档，修正版在同等口径下 0 错误 |
| §2.1-5 | 规则散落、非常量 | 提取 `MAX_TITLE_CHARS`/`MAX_CONTENT_BYTES`/`DEFAULT_TITLE`/`DEFAULT_LIMIT`/`MAX_LIMIT` 顶层常量 |
| F12（部分） | 夹带 `.cargo/config.toml`（rsproxy 个人镜像） | 修正版不含该文件，使用默认注册表 |
