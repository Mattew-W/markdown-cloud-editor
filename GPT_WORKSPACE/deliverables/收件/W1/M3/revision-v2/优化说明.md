# 优化说明：M3_W1 密码校验小程序 v2

对象：M3 W1 交件 `M3_W1.zip` 中的 `password_demo`（v1）。
本目录是**独立新增**的优化版本，**不修改、不覆盖**原交件（`extracted/` 保持字节级原样）。

---

## 一、v1 → v2 改动对照

| 维度 | v1（原交件） | v2（优化后） | 改动理由 |
|---|---|---|---|
| 代码结构 | 全部逻辑写在 `src/main.rs`（95 行） | 拆为 `src/password.rs`（核心）+ `src/lib.rs`（库导出）+ `src/main.rs`（演示） | 主项目集成时可直接引用库，不必从可执行文件里抠代码 |
| 错误处理 | 返回 `argon2::password_hash::Error`，靠 `Err(Error::Password)` 模式匹配区分「密码错」 | 自定义 `PasswordError` 五个变体：`InvalidHashFormat` / `IncompatibleParams` / `PasswordMismatch` / `HashingFailed` / `InvalidParams` | 上层接口能把「用户密码错」和「数据被篡改」分开处理，登录接口不需要靠字符串猜 |
| 参数配置 | 写死 `Argon2::default()`（m=19456, t=2, p=1） | `Argon2Params` 结构体，m/t/p/output_len 全部可配 | 便于纳入 `config.rs`，按服务器性能调优 |
| 残缺哈希串 | `$argon2id$v=19$m=...,t=...,p=1`（无 salt/hash）会被库返回 `Error::Password`，**误判为密码错误** | 显式前置检查 `salt`/`hash` 字段，缺字段一律报 `InvalidHashFormat` | 避免把「数据损坏」当成「用户输错密码」，后者会误导登录失败提示 |
| 演示内容 | 4 个案例 | 5 个案例（新增密码策略检查） | 策略检查是 W2 选做项的预置，纯字符级判断，不涉及数据库 |
| 单元测试 | 无 | 10 个（`cargo test` 全部通过） | 覆盖正确 / 错误 / 损坏 / 残缺 / 空串 / 参数非法 / 盐随机性 / 参数随哈希走 / 策略 |
| 代码格式 | `cargo fmt --check` **未通过** | `cargo fmt --check` 通过 | 本项目 CI 会跑 fmt，正式代码必须过 |
| 静态检查 | clippy 通过 | clippy `--all-targets -- -D warnings` 零警告 | 把警告当错误，避免遗留 lint |
| 文档 | 注释较简 | 每个公开项带 `///` 文档注释 + `# Errors` 段 | Rustdoc 是课程要求，错误返回必须说明 |

## 三、一个需要说明的实现细节

v2 的「校验沿用哈希串自带参数」这一点，最终是**依赖库自身行为**实现的，而不是手写解析：

`password-hash 0.5` 的 `PasswordVerifier` 为所有 `PasswordHasher` 提供了默认实现，其中执行
`hash_password_customized(password, Some(hash.algorithm), hash.version, T::Params::try_from(hash)?, *salt)`——
即算法、版本、m/t/p 参数**全部取自哈希串本身**。

第一版实现曾尝试手工从 `PasswordHash` 反解 `Algorithm` / `Version` / `Params` 再构造 `Argon2` 实例，
但 argon2 0.5.3 并未提供 `Algorithm: TryFrom<&PasswordHash>` 这类转换（只有 `TryFrom<Ident>`），
编译直接失败。改为直接调用库的默认验证路径后，既通过编译，语义又更准确。

**这意味着调参安全性是库保证的**，不是本实现额外做的，注释中已如实标注。

## 四、复现方式（含一个必须注意的环境坑）

```powershell
# 1. 复制到纯 ASCII 路径（原因见下）
Copy-Item -Recurse -LiteralPath "<本目录>\password_demo" -Destination "纯 ASCII 示例目录"
cd 纯 ASCII 示例目录

# 2. 依次执行
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets      # 注意：必须带 --all-targets，理由见下
cargo run
```

**测试参数坑（2026-10-20 复核时发现，比环境坑更容易误导）**：
10 个 `#[test]` 全部位于 `src/password.rs` 的 `#[cfg(test)] mod tests`，即 **lib target** 内。
`cargo test` 默认**只跑 bin target**，会输出 `running 0 tests` 且**退出码为 0**——
看上去"测试通过"，实际一个测试都没执行。必须写：

- `cargo test --lib`（只跑库），或
- `cargo test --all-targets`（库 + bin，**推荐**，与 CI 口径一致）

用 `cargo metadata` 可确认 lib/bin 两个 target 都已被正确识别；
若怀疑 target 缺失，先查它再查代码。

**环境坑（重要）**：在含中文的路径下（例如改名前的 `[本地工作区路径已脱敏]\...`）执行 `cargo run`
会在链接阶段失败：

```
error: linking with `x86_64-w64-mingw32-gcc` failed
ld: cannot find ...\target\debug\deps\rustcXXXX\symbols.o: No such file or directory
```

根因是 GNU 工具链的 mingw-w64 链接器无法处理非 ASCII 路径，**与代码无关**（`cargo clippy`、
`cargo test` 在中文路径下都正常，只有链接环节挂）。

补充实测（2026-10-20）：仅把 `CARGO_TARGET_DIR` 或 `.cargo/config.toml` 的 `target-dir`
设为**绝对** ASCII 路径即可，无需搬动源码；但**相对路径无效**——链接器解析 `..` 后仍会拼上
含中文的上级目录。

本机所有 Rust 编译/运行测试今后一律放 ASCII 路径，或使用上述 target-dir 配置。

## 五、集成到主项目的方式（M1 参考）

1. 把 `src/password.rs` 迁入主项目 `src/auth/password.rs`（或 `src/auth/mod.rs` 的子模块）；
2. 保留 `hash_password` / `verify_password` 两个公开函数名与签名，调用方无需改动；
3. `Argon2Params` 的默认值从 `config.rs` 读取（环境变量 `ARGON2_MEMORY_KIB` 等），缺省回落到库默认；
4. `PasswordError` 五个变体映射到主项目统一错误类型：
   - `PasswordMismatch` → HTTP 401（凭据错误）
   - `InvalidHashFormat` / `IncompatibleParams` → HTTP 500（数据异常，应告警而非提示用户）
   - `HashingFailed` / `InvalidParams` → HTTP 500（服务配置或运行异常）
5. `PasswordPolicy` 在注册 / 改密接口最前端调用，返回违规项列表供前端提示；
6. 迁移后主项目 CI 的 `fmt` / `clippy` / `test` 必须仍全绿。

**注意**：本目录是**练习优化版本**，不是已并入主项目的生产代码。主项目正式认证模块由 M1 决定归属与落位。
