### 3.2 `token.rs` 的改动

**生产代码改动仅 1 处**（4 行）：

```rust
-    if data.claims.sub.is_empty() {
+    if data.claims.sub.trim().is_empty() {
```

即：把「空 `sub`」扩展到「纯空白 `sub`」（空格 / 制表符 / 全角空格 U+3000）。理由正确——`sub` 承载用户 UUID，纯空白串同样会导致「验签通过但查不到用户」。且**只判空不裁剪**，合法 id 原样透出，不做任何改写。

其余 250 行全部是新增测试。

### 3.3 `password.rs` 的改动——本次最有价值的部分

新增 `ensure_verifiable()` 参数闸 + 3 个上限常量：

```rust
const MAX_VERIFY_MEMORY_KIB: u32 = 1_048_576; // 1 GiB
const MAX_VERIFY_ITERATIONS: u32 = 64;
const MAX_VERIFY_PARALLELISM: u32 = 8;
```

在 `verify_password` 中，`PasswordHash::new()` 解析之后、交给 argon2 之前插入：

```rust
ensure_verifiable(&parsed)?;
```

**这修掉了一个真实的 DoS 漏洞。** `argon2` 会按哈希串里的 `m` 直接申请内存。一条 `m=4294967295` 的损坏记录 = 要求 4.4 TB 内存，分配失败时**进程直接中止**（不是返回错误），整个服务连同其他请求一起死。`t` 同理，上亿次迭代会把线程卡死数小时。

**M3 的实现细节值得称赞**：它**直接读 PHC 串里的十进制字段**（`parsed.params.get_decimal("m")`），而不是构造 `argon2::Params`——因为 `Params::try_from` 内部要算 `8 * p`，遇到 `p=4294967295` 时在 debug 下会触发「attempt to multiply with overflow」panic（release 下静默回绕）。用 `try_from` 做损坏数据的闸门并不可靠。这个陷阱识别得很准。

**本机独立实测（决定性证据）**：

```
=== 模式 gate（有闸门）===
闸门拦下：内存参数 4294967295 KiB 超过上限 1048576 KiB，未进入 argon2
GATE_EXIT=0

=== 模式 nogate（无闸门，直接进 argon2）===
Params::try_from 结果: Ok(4294967295)
memory allocation of 4398046507008 bytes failed
NOGATE_EXIT=-1073740791        ← 0xc0000409 STATUS_STACK_BUFFER_OVERRUN
```

组员的 `日志/06_修复前_参数OOM用例.txt` 记录的数值与此**完全一致**（4398046507008 字节、exit code 0xc0000409）。

### 3.4 与冻结契约的一致性

`docs/INTERFACES.md` §1.3 要求：`IncompatibleParams` → **500 INTERNAL_ERROR**，且「`InvalidHashFormat` **绝不能**映射成 `PasswordMismatch`」。

M3 的参数闸返回 `PasswordError::IncompatibleParams`，**与契约一致**。新增用例 `损坏格式与不兼容参数都不得归类为密码不匹配` 对 11 条改造串逐条断言 `!matches!(err, PasswordError::PasswordMismatch)`，正面覆盖了契约红线。
