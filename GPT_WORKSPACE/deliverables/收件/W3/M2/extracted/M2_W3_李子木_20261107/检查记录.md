## 3. 既有 W2 的 11 例与事务回滚（复述，不是本次执行）

W2 的基线脚本：

```powershell

psql -X -v ON_ERROR_STOP=1 -d <练习库名> -f migrations/checks/run_checks.sql
```

`run_checks.sql` 的机制：

1. `ON_ERROR_STOP` 使任一语句失败时 psql 退出。
2. `BEGIN` 开启外层事务。
3. `\ir fixtures.sql` 插入 3 个用户、6 篇文档。
4. `\ir verify_constraints.sql` 执行 11 例。
5. `ROLLBACK` 丢弃夹具和合法边界测试行，成功时业务表零残留。

每条负例在嵌套 `BEGIN/EXCEPTION` 子事务中执行；用 `GET STACKED DIAGNOSTICS`
捕获 `RETURNED_SQLSTATE`，与预期比较；未报错或错误码不同都显式 `RAISE EXCEPTION`，
不使用 `WHEN OTHERS THEN NULL` 吞错。合法边界用真实 INSERT，随后删除/回滚。

## 7. W2 解释纠偏

- 整数 `99999` 不是合法 UUID，不能用来测 UUID 外键。
  - 对 UUID 列**赋值**（如 `INSERT ... VALUES (99999)`）是类型不匹配，常见 `42804`。
  - 对 UUID 列**比较**（如 `WHERE owner_id = 99999`）具体错误码取决于语句，
    常见 `42883`（没有 `uuid = integer` 运算符）。
  - 字符串 `'99999'` 才会进入 UUID 输入解析，报 `22P02`。
- 只有语法合法但未插入 `users` 的 UUID（如 `99999999-9999-4999-8999-999999999999`）
  才会触发外键检查并得到 `23503`。
- 以上按 SQL 语义说明；本机无 PostgreSQL，未能实测，具体以实际执行语句与输出为准。
