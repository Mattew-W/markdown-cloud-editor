## 1. 项目目标

**Web-based Markdown Editor with Cloud Sync**

用户注册或登录后，可以创建、列出、读取、修改和删除**自己的** Markdown 文档。编辑页面提供**左侧 textarea + 右侧预览 div**；修改通过后台自动保存持久化，重新登录或更换设备后可以读取已同步内容。

## 2. MVP 范围

### 2.1 必须实现的六项能力

| # | 能力 | 验收要点 | 相关文档 |
| --- | --- | --- | --- |
| 1 | **账号认证与逐个资源的所有权检查** | JWT 固定 HS256；`owner_id` 从已验证身份读取；越权与不存在**统一 404** | [`API.md`](API.md) §1.1、§11 |
| 2 | **文档完整生命周期及 PostgreSQL 持久化** | CRUD 五端点齐全；`version` 乐观锁；服务重启后可读取已保存数据 | [`API.md`](API.md) §5–§9、[`DATABASE.md`](DATABASE.md) |
| 3 | **Markdown 实时预览和 HTML 安全净化** | `DOMPurify.sanitize(marked.parse(text))`；标题与错误消息用 `textContent` | [`ARCHITECTURE.md`](ARCHITECTURE.md) §3.4 |
| 4 | **自动保存、保存状态提示和编辑焦点保持** | 防抖 1.5 秒 / max-wait 5 秒；在途上限 1；**不重建编辑节点** | [`SYNC.md`](SYNC.md) §2、§4 |
| 5 | **文档版本冲突检测、本地草稿和异常恢复** | 409 冲突；四分支核对；草稿键含 user/doc/session 三元组 | [`SYNC.md`](SYNC.md) §6、§9 |
| 6 | **PR 审核、自动化检查、可重复启动和真实测试记录** | 四个必需检查；可从空环境按 README 跑起来 | [`ARCHITECTURE.md`](ARCHITECTURE.md) §8 |

| 表 | 字段数 | 说明 |
| --- | --- | --- |

## 3. 非目标（首版明确不做）

> **以下功能首版一律不实现。** 看到需求想加进来时，先查本节。

| # | 不做的功能 | 理由 |
| --- | --- | --- |
| 1 | **修订历史 / 完整历史版本** | 需要独立的版本表与差异存储。首版只有 `version` 单值，用于乐观锁，**不是历史记录** |
| 2 | **实时协同编辑** | 需要 CRDT 或 OT 算法与 WebSocket。首版**明确排除 CRDT、WebSocket** |
| 3 | **移动端适配** | 首版面向桌面浏览器双栏布局 |
| 4 | **共享权限 / 文档分享** | 首版是**个人云文档**，不做他人只读链接 |
| 5 | **附件上传** | 首版无对象存储 |
| 6 | **离线新建文档队列** | 首版离线时**不创建云端占位文档** |
| 7 | **搜索** | 先完成核心验收 |
| 8 | **Markdown 导出** | 同上。但**本地备份失败时的 `.md` 下载兜底是必做**（[`SYNC.md`](SYNC.md) §9.8） |
| 9 | **主题切换** | 同上 |
| 10 | **刷新令牌（refresh token）** | token 过期后重新登录。首版不实现刷新服务 |
| 11 | **token 吊销 / 黑名单** | 退出只清理客户端。**已知限制**，见 §3.1 |
| 12 | **用户删除 / 账号注销** | 支撑 `ON DELETE RESTRICT` 的选择（[`DATABASE.md`](DATABASE.md) §4.3） |
| 13 | **创建文档的幂等键协议** | `POST` 响应丢失时不自动重发，先提示用户核对。**若将来要做须单独设计**（[`SYNC.md`](SYNC.md) §10） |
| 14 | **HTTP/2、gRPC、WebSocket** | 单一 HTTP/JSON 契约 |
| 15 | **Rust workspace（多 crate）** | 首版一个 crate |

### 3.1 已知限制（非目标，但须在交付文档中说明）

这些**不是**"暂缓实现"，而是**首版已知的、被接受的设计取舍**：

| # | 限制 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 1 | **已签发 token 在退出后至到期前仍有效** | 最长 1 小时的窗口 | 必须写入 `SECURITY.md` |
| 2 | **`sessionStorage` 可被同源脚本读取** | XSS 即凭据泄露 | XSS 防护是硬要求，非可选项 |
| 3 | **非正常关闭可能丢失最后一小段输入** | 250 毫秒合并窗口内的输入 | **不得承诺绝对不丢失** |
| 4 | **`navigator.onLine` 不可信** | 浏览器报"在线"不代表请求成功 | 只用于提示与触发尝试 |
| 5 | **`btrim` 不识别 Unicode 空白** | `title = '　'`（U+3000）能通过 DB `CHECK` | **应用层才是真正防线**（[`DATABASE.md`](DATABASE.md) §4.4） |

## 4. 语言占比

### 4.1 目标与范围

| 语言 | 目标占比 | 合理波动范围 | 主要内容 |
| --- | --- | --- | --- |
| **Rust** | **60%** | 55%–65% | API、认证、服务、数据库访问、后端测试 |
| **JavaScript** | **25%** | 20%–30% | 页面行为、预览、保存状态机、前端测试 |
| **CSS** | **7%** | 5%–10% | 布局、编辑器排版、状态与响应式样式 |
| **HTML** | **5%** | 3%–7% | 页面结构、表单和可访问性语义 |
| **SQL** | **3%** | 2%–5% | 迁移、约束和必要的数据脚本 |

目标合计 100%。范围表示各项**可单独波动**，并非要求范围上下限相加为 100%。

### 4.2 统计口径

| 项 | 规则 |
| --- | --- |
| **计入** | **自写有效代码行**，**包含**对应语言的测试 |
| **排除** | 空行、纯注释行、第三方库、生成文件、锁文件、构建产物 |
| **SQL 特例** | **内嵌在 Rust 字符串中的 SQL 默认随所在 Rust 文件统计，不重复计数** |
| **文档/配置** | Markdown、YAML、TOML、JSON、PowerShell **单独统计**，不计入上表 |

### 4.3 Linguist 与本口径的关系

**GitHub 的语言栏使用 Linguist，按符合条件文件的字节数计算，与有效代码行不同。**

> **GitHub 展示比例不能直接证明符合课程要求，也不能替代工作量评估。**

`.gitattributes` 中必须**如实标记**第三方代码：

```gitattributes
frontend/vendor/** linguist-vendored=true
```

> **不得**把自己编写的 JavaScript、CSS 或测试标记成第三方代码来提高 Rust 展示比例。第三方库仍需保留版本、来源和许可证。

### 4.4 语言约定

| 类别 | 语言 |
| --- | --- |
| 团队沟通文档 | **中文** |
| API 字段、代码标识符、错误码、目录 | **英文** |
| Rustdoc | 团队一致的语言，描述**行为、错误与边界** |
| 提交信息 | 中英文均可，但**必须表达具体变更** |

## 6. 验收矩阵

> 下表来自项目规范 §11，**是本项目的验收权威清单**。共 15 项，覆盖正常路径、异常路径与安全边界。

| 编号 | 场景 | 通过标准 | 契约出处 |
| --- | --- | --- | --- |
| **T01** | 注册登录与过期 token | 正确状态码；无密码哈希泄漏；失效 token 被拒绝 | [`API.md`](API.md) §3、§4、§11 |
| **T02** | 跨账号读取更新删除 | **全部被拒绝**；原文档和版本不变 | [`API.md`](API.md) §1.1、§7.4 |
| **T03** | CRUD 与服务重启 | 完整生命周期正确；**重启后可读取已保存数据** | [`API.md`](API.md) §5–§9 |
| **T04** | 相同版本并发更新 | **仅一次成功**，其余冲突，**数据未被静默覆盖** | [`DATABASE.md`](DATABASE.md) §6.2 |
| **T05** | 保存中继续输入 | 确认只覆盖发送快照，后续字符继续保存 | [`SYNC.md`](SYNC.md) §4.1、§4.3 |
| **T06** | A 文档切换到 B | **A 的旧响应不污染 B 的内容、版本和状态** | [`SYNC.md`](SYNC.md) §8.2 |
| **T07** | 已落库但响应丢失 | 能核对结果；**不无条件覆盖或误报未保存** | [`SYNC.md`](SYNC.md) §6.2 |
| **T08** | 离线与恢复 | 草稿可恢复；**云端未确认前不显示已同步** | [`SYNC.md`](SYNC.md) §9.7、§4.2 |
| **T09** | 多窗口与删除冲突 | **草稿分离**；旧版本删除被拒绝 | [`SYNC.md`](SYNC.md) §1.1、§9.2；[`API.md`](API.md) §9.4 |
| **T10** | 本地存储失败 | 显示备份失败并**允许下载**；**不虚报本地已保存** | [`SYNC.md`](SYNC.md) §9.8 |
| **T11** | 401 409 413 429 5xx | 分别进入约定状态，**避免无限快速重试** | [`SYNC.md`](SYNC.md) §5、§7.2 |
| **T12** | XSS 与恶意标题 | **脚本未执行**，标题按文本显示 | [`ARCHITECTURE.md`](ARCHITECTURE.md) §3.4 |
| **T13** | 焦点和中文输入 | 自动保存**不重建编辑节点**，不干扰选区与组合输入 | [`SYNC.md`](SYNC.md) §2.4 |
| **T14** | 输入和分页边界 | 空标题、超限正文、非法 UUID、非法分页**均按契约处理** | [`API.md`](API.md) §1.3 |
| **T15** | 完整演示 | 登录、编辑、保存、另会话读取、冲突处理**可重复完成** | [`PROJECT_SPEC.md`](PROJECT_SPEC.md) §2.3 |

### 6.1 测试记录要求

| 项 | 要求 |
| --- | --- |
| **必含字段** | 命令、环境、commit SHA、日期、结果 |
| **失败、未执行、跳过** | **三者分别记录**，不得合并为"其他" |
| **未运行不能标为通过** | 收件流程第 4 步的硬要求 |
| **单元测试** | **使用可控时钟**模拟防抖、最大等待和重试，**避免依赖真实长时间等待** |
| **性能目标** | 须记录**设备、浏览器、文本规模和测量方法**。**不能直接引用报告中的毫秒数作为实测成绩** |

### 6.2 关键测试的三条实现提示

| 验收项 | 关键测试点 | 失败模式 |
| --- | --- | --- |
| **T04** | 两个连接用**同一 `expected_version`** 并发更新 | 先 SELECT 再 UPDATE 的写法会**两个都成功**，静默丢数据 |
| **T07** | 模拟"服务端已提交但响应丢失" | 若信任 `navigator.onLine`，会**显示已同步但数据没上去** |
| **T10** | 注入存储**配额耗尽**与**存储禁用** | 若把 `e.message` 直接透出，会显示 `"The operation is insecure."` |
